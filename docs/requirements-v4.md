# ローカル音声作品管理・再生アプリ 要件定義

> 要件と実装が食い違ったときは、バグか要件の陳腐化として扱い、どちらを正とするかはADRで決める。アーキテクチャの現行は [ARCHITECTURE.md](ARCHITECTURE.md)、開発の現状は [HANDOFF.md](HANDOFF.md) を参照。

## 1. 概要

### 1.1 背景

DLsiteやDMMのWebプレイヤーが使いにくく、横断的な検索ができない。ローカルに保存した音声作品を快適に管理・再生するアプリが必要。

### 1.2 コンセプト

**タグによる分かりやすい検索性**と、**物理的なフォルダーによる手動での管理性**の両立。

### 1.3 ターゲットプラットフォーム

- v1: Windows / macOS / Linux でローカル起動する Web アプリ（ブラウザ + ローカル API サーバー）
- 将来: リモート端末（iPad等）からの LAN ストリーミングを視野に入れる

### 1.4 技術スタック

- **フロントエンド:** React 19 + TypeScript + Vite
- **バックエンド:** TypeScript + Hono + Bun（ローカル HTTP API サーバー。[ADR-0007](adr/0007-bun-distribution-runtime.md)）
- **音声再生:** HTML5 Audio + Web Audio API（フロントエンド完結）
  - 将来的に高度な機能（ギャップレス再生等）が必要になった場合、サーバー側への移行余地を残す
- **データベース:** SQLite（作品カタログとユーザー状態の2ファイル）
- **設計方針:** ローカルUIとリモートUIで同じ API を共有できる設計。モックはフィクスチャアダプタとして実データ経路と同じ境界に置く（[ADR-0002](adr/0002-mock-as-fixture-adapter.md)）。

### 1.5 対応音声フォーマット

HTML5 Audio（ブラウザの Chromium エンジン）のサポート範囲に準拠する。

**対応フォーマット:** MP3, AAC/M4A, WAV, OGG (Vorbis), FLAC, WebM/Opus

**非対応（将来検討）:** WMA, ALAC, DSD 等

DLsite作品の大半はMP3かWAV、FANZAはM4Aが多いため、上記で実用上ほぼカバーできる。非対応フォーマットのトラック単位グレーアウト表示は未実装（将来候補）。再生時にデコードエラーが起きた場合はエラー状態として扱う。

## 2. 作品の管理

### 2.1 作品の形式

作品は以下の2形式をサポートする。

**フォルダー形式:** 販売サイトからダウンロードしたファイル一式が1フォルダーにまとまった形式。フォルダー内には複数の音声ファイル、画像ファイル、PDF、テキストファイルが含まれる。1つの作品内にSE有無やフォーマット違い（mp3/wav）など複数のバリアントが存在するケースがある。

**単一ファイル形式:** 音声作品の全トラックを結合した1ファイル（mp3, m4a等）。チャプター情報に基づきトラックごとに再生する。

### 2.2 フォルダー構造

ユーザーが指定したルートフォルダー以下を管理対象とする。ルート直下に全作品がある必要はなく、ユーザーが自由なフォルダー構造で保存できる。

```
root/
├── dlsite/
│   ├── genre-a/
│   │   └── RJ1234/              ← フォルダー形式の作品
│   │       ├── SE有り/mp3/
│   │       ├── SE無し/mp3/
│   │       ├── cover.jpg
│   │       └── mimimilli.json
│   └── genre-b/
│       └── RJ5678/
└── fanza/
    ├── d00001.mp3                ← 単一ファイル形式の作品
    └── d00001.mimimilli.json
```

### 2.3 作品の認識とスキャン

作品フォルダー内、または単一ファイルと同階層に**メタファイル（`mimimilli.json`）**を配置することで作品として認識する。スキャン時にメタファイルを検出し、内部DBと同期する。メタファイルのないフォルダーは、スキャンが「未登録の候補」として挙げる。メタファイルはユーザーが登録操作をしたときに作られる（3.5項）。

### 2.4 作品IDと移動追従

メタファイル内にUUID形式の作品IDを保持する。ユーザーがフォルダーやファイルを物理的に移動・リネームした場合、スキャン時にIDで突合しDBのパス情報を更新する。DB上に存在するがスキャンで見つからない作品は「行方不明」ステータスとする。

## 3. メタデータ

### 3.1 二重管理方式

メタファイル（`mimimilli.json`）をSource of Truthとし、内部DB（SQLite）は検索・一覧のパフォーマンス用キャッシュとして運用する。DB側で編集した場合はメタファイルに即時書き戻す（DB編集とメタファイル更新を同一操作内で行う）。

アプリが起動していない間にユーザーがメタファイルを手動編集した場合、次回スキャン時にメタファイルの内容でDBを上書きする（メタファイルが常に勝つ）。

複数のメタファイルに同一UUIDが存在した場合、routine scan は自動再採番せず `identity_conflict` として診断・表示する。ユーザーが明示操作で再採番する（[ADR-0017](adr/0017-meta-source-projection-and-work-identity.md)）。

### 3.2 メタファイル フォーマット

フォーマットの正典はコード側のスキーマ定義（`shared/`）。作品・プレイリスト・トラックはそれぞれ UUID v4 の `id` を持ち、メタファイルの作成時に自動生成される。

```jsonc
{
  "id": "<uuid>",
  "title": "作品タイトル",
  "urls": [
    { "label": "DLsite", "url": "https://www.dlsite.com/..." },
    { "label": "FANZA", "url": "https://www.dmm.co.jp/..." },
  ],
  "tags": ["R-15", "バイノーラル", "cv/ひなたゆか", "サークル/ほげふが"],
  "coverImage": "cover.jpg",
  "playlists": [
    {
      "id": "<uuid>",
      "name": "default",
      "tracks": [
        { "id": "<uuid>", "title": "導入", "file": "SE無し/mp3/01_導入.mp3" },
        { "id": "<uuid>", "title": "本編", "file": "SE無し/mp3/02_本編.mp3" },
      ],
    },
  ],
  "defaultPlaylistId": "<uuid>",
  "createdAt": "2025-01-01T00:00:00Z",
}
```

`urls` は作品に関連するURLの配列。販売ページ（DLsite, FANZA）、作者のSNS、公式サイトなどを複数登録できる。通常は1〜2件、多い場合で3〜5件を想定。`label` はUI表示用の短いラベル。空配列の場合はURLなしとして扱う。

### 3.3 トラック定義

トラックのスキーマはフォルダー形式・単一ファイル形式で統一する。各トラックは「どのファイルのどの区間を再生するか」を表す。

```jsonc
// フォルダー形式: ファイルパスのみ（区間省略 = ファイル全体）
{ "title": "導入", "file": "SE無し/mp3/01_導入.mp3" }

// 単一ファイル形式: 同一ファイルに対して区間指定（秒）
{ "title": "導入", "file": "d00001.m4a", "start": 0, "end": 180 }
```

`start`/`end` が省略されている場合はファイル全体を再生する。これによりプレイヤー側のロジックは常に「指定ファイルの指定区間を再生する」の1つで統一される。単一ファイルのチャプター情報のソースは、ファイル内蔵のチャプターマーカーまたはユーザー手動設定とする。`tracks` が未定義の場合は1トラック（ファイル全体）として扱う。

チャプターの自動読み取りと手動設定UIは現在提供しない。単一ファイル形式を使う場合は、メタファイルのトラック定義で区間を指定する。

### 3.4 作品内プレイリスト

`playlists` 配列により、1作品に対して複数のトラック構成を持てる。SE有無やフォーマット違いなどのバリアントに対応する。

```jsonc
"playlists": [
  { "id": "<uuid>", "name": "SE無し", "tracks": [/* ... */] },
  { "id": "<uuid>", "name": "SE有り", "tracks": [/* ... */] }
],
"defaultPlaylistId": "<SE無しのuuid>"
```

大半の作品ではプレイリストは1つのみの想定。データ構造は複数プレイリストに対応するが、管理UIは現在提供せず、プレイヤーは `defaultPlaylistId` のプレイリストを再生する。

### 3.5 作品の登録とメタファイルの作成

メタファイルは、ユーザーが作品として登録したときに作成する。スキャンはメタファイルを書かない。メタファイルがなく音声ファイルを含むフォルダーは、スキャンが「未登録の候補」として挙げるだけである。登録の入口は2つある。

- **スキャンの未登録タブ:** 候補フォルダーを選んで登録する。RJコードはフォルダー名から自動で拾い、未検出なら行ごとに直せる。形式が不正なRJコードの行は、直すまで登録対象から外れる。見送りたい候補は候補から外せ、外したフォルダーは後から戻せる。
- **Filesモード:** フォルダーまたは音声ファイルを選び、「作品として登録」する。単一ファイル形式の作品はこの入口で登録する（スキャンは候補にしない）。以前の登録情報（メタファイル）が残っている場所は、その内容を引き継いで復元する。登録済み作品の配下や、登録済みフォルダーの内側は登録できない。

登録した作品は、DLsite一括取得の対象として自動でキューに積まれる。登録の解除はメタファイルを削除する操作で、音声などのファイルは残る。

**作成するメタファイルの内容（フォルダー形式）:**

- `id`: UUID自動採番
- `title`: フォルダー名。フォルダー名にRJコードがあればDLsiteの作品コードとして保持する
- `urls`: 空配列（手動追加またはDLsite情報の適用時に設定する）
- `tags`: 空配列（手動追加またはDLsite情報の適用に委ねる）
- `coverImage`: フォルダー内の画像ファイルを探索し、あれば最初の1枚を設定（なければnull）
- `playlists`: フォルダー内の音声ファイルをファイル名の自然順ソートで列挙し、`default` プレイリストとして生成。サブフォルダーが複数ある場合（`SE有り/`, `SE無し/` 等）は、最もファイル数が多いサブフォルダーの音声ファイルを `default` プレイリストとする

**単一ファイル形式:** 音声ファイルと同じ階層に `<ファイル名>.mimimilli.json` を作る。トラックはファイル全体を1本とし、タイトルはファイル名から付ける。区間分割は3.3項のとおりメタファイルを直接編集する。

### 3.6 DB固有の情報（メタファイルには保存しない）

以下の情報はDBのみで管理する。

- 作品の物理パス（スキャン時に更新）
- 再生位置と対象トラック（レジューム情報）
- 作品のステータス（正常 / 行方不明 / エラー）
- デフォルトプレイリストの合計再生時間（スキャン時またはメタデータ更新時に算出しキャッシュ）
- ブックマーク状態
- 最終再生日時

## 4. タグシステム

### 4.1 タグの種類

**フラットタグ:** 単純な文字列。ジャンルや属性を表す。例: `R-15`, `バイノーラル`, `触手`, `耳かき`

**Annotatedタグ:** スラッシュ区切りで構造的に管理するタグ。`カテゴリ/値` の形式。最初のスラッシュでのみ分割する（値にスラッシュが含まれる場合でも正しく処理される）。例: `cv/ひなたゆか`, `サークル/ほげふが`, `シリーズ/○○物語`

### 4.2 タグの運用

タグは作品の唯一の属性機構とする。サークル名、CV、ジャンル等も専用の属性ではなくタグとして管理し、1つの作品に多数のタグが付くことを前提とする。属性の構成はシステムが固定せず、ユーザーがフラットタグとAnnotatedタグを自由に追加・削除できる。

Annotatedタグの表示や操作上の特別扱いは、ユーザーが編集できるprefix定義で管理する。保護されたprefixのタグも編集できるが、削除時には確認ダイアログを表示する。

### 4.3 DB設計とパフォーマンス

DBは、メタファイルやファイル走査から再構築できる作品カタログと、ブックマーク・最終再生日時・再生位置・prefix定義などDBが正本のユーザー状態の2ファイルに分離する。検索・ソート・軸ファセット集計・件数・ページングはサーバー側のSQLで処理する。設計判断は[ADR-0008](adr/0008-persistence-topology-query-ownership-playback-ids.md)を参照。

### 4.4 DLsiteからのタグ自動取得

DLsiteの作品ページからスクレイピングしてタグを自動取得する。ジャンルは `genre/耳かき` のように、年齢指定は `rating/R18` のようにprefix付きで変換する。取得対象はタイトル、サークル名、CV、ジャンルタグ、年齢指定（全年齢 / R15 / R18）、カバー画像など。RJコードがフォルダー名に含まれる場合、DLsiteの作品コードとして扱う。

### 4.5 prefix定義（タグ設定）

prefix定義はAnnotatedタグの表示ラベル、色、軸レールへの表示、削除時の保護を表す設定データである。設定モーダルの「タグ設定」で追加・変更・削除でき、作品データに存在する未登録prefixも候補一覧から登録できる。アプリは特定のprefixを特別扱いしない。

初回のみ、次のprefix定義を初期値として用意する。`cv`（ラベル: CV、保護、軸表示）、`サークル`（保護、軸表示）、`シリーズ`（軸表示）、`カテゴリ`（軸表示）、`genre`（ラベル: ジャンル、軸非表示）、`rating`（ラベル: レーティング、軸表示）。以降の追加・変更・削除はユーザーの自由であり、すべて削除しても初期値は戻さない。

分類軸は、軸表示がONのprefix定義を定義順に並べ、組み込みのタグ軸と追加日軸を加えて動的に構成する。追加日軸はタグ由来ではなく、作品の追加日の年から導出する。

タグは保存時に正規化する。prefixは前後の空白を除いて小文字にし、値は前後の空白を除く。prefixの比較は大文字小文字を無視し、値は区別する。タグ絞り込みと軸ドリルはタグ全体の完全一致、グローバル検索ボックスだけは部分一致とする。

保護は編集禁止ではなくソフトガードである。保護されたprefixのタグを削除するときだけ確認ダイアログを表示し、ユーザーが確認すれば削除できる。設計判断の詳細は[ADR-0005](adr/0005-tags-as-sole-attribute.md)を参照。

## 5. プレイヤー機能

### 5.1 現在の再生機能

- 基本再生: 再生 / 一時停止 / 停止
- シーク（再生位置の移動）
- 音量調整
- トラック切り替え（前へ / 次へ）
- 作品内の連続再生
- ±10秒ジャンプ（ASMR作品では再生位置の微調整が重要なため、標準コントロールとして提供）
- ループ再生（現在のトラックをリピート）
- 再生速度変更
- L/R入れ替え
- A-Bリピート。A点とB点は再生中のトラックで設定し、トラック切り替え時に解除する。ポイントは永続化しない
- レジューム。再生位置（プレイリスト・トラック・区間内オフセット秒）をDBへ5秒間隔、一時停止時、停止時、トラック切り替え時に保存し、作品詳細の「続きから」で再開する
- OSのメディアコントロール連携。対応ブラウザーでは作品・トラック情報、カバー、再生状態、再生位置をOSへ公開し、再生、一時停止、前後トラック、前後シーク、位置指定を受け付ける

### 5.2 プレイヤーの表示モード

プレイヤーは、バー、ポップアップ、再生中タブの3つの表示を持つ。再生対象が読み込まれている間（一時停止中も含む）は、再生中タブ以外の画面でバーまたはポップアップのどちらかが常に表示される。再生中タブを表示している間は、再生中タブ自身が操作部を持つため、バーとポップアップは表示しない。再生対象が読み込まれていない間は、バーもポップアップも表示しない。

**バー:** 画面下部に常駐するコンパクトなコントロール。カバー、トラック名/作品名、前へ/再生・一時停止/次へ、シークバー、音量、展開ボタン、停止ボタンを備える。バー本体（操作ボタン以外）のクリックまたは展開ボタンでポップアップへ切り替わる。

**ポップアップ:** 画面右下を初期位置に表示されるカード形式のコントロール。カバー大表示、±10秒ジャンプ、シーク、音量、ループ、再生速度メニューを備える。ヘッダーから、再生中の作品をライブラリで表示（Filesから再生したファイルでは出ない）、バーへ戻る、再生中タブを開く、再生を停止、の操作ができる。ドラッグで画面内の任意の位置へ移動でき、位置は端末に永続化され次回もその位置で開く。ダブルクリックで初期位置へ戻る。

**再生中タブ:** 左ナビの「再生中」ボタンから、再生の有無にかかわらず開ける。再生対象がないときは「再生中の作品はありません」と表示する。再生対象があるときは、通常モード（左カバー / 右トラックリストの横長2カラム + 下部固定バー）と没入モード（カバーが画面全面を覆う）を切り替えられる。カバー画像、トラックリスト、L/R入れ替え、A-Bリピートを含む再生操作を表示する。通常/没入の別は端末に永続化され、再生中タブへ再訪した際に復元される。

バーとポップアップの別は端末に永続化され、再生中タブから戻ったときや次回の再生時にその表示で現れる。

### 5.3 再生モード

**トラックモード:** メタファイルのプレイリスト（`defaultPlaylistId` が指すもの）に基づき、音声ファイルをトラックリストとして表示。トラック単位の再生が可能。

プレイヤー内のフォルダービューは現在提供せず、Filesモードを別画面として提供する。

### 5.4 将来候補

- フォルダービュー（作品フォルダーの物理構造を表示し、音声・画像・PDFを閲覧）
- A-Bリピートのポイント保存
- バックグラウンド再生 + グローバルホットキー
- ギャップレス再生（サーバー側での実装を検討）
- プレイリスト（作品横断）

## 6. エラーハンドリング

### 6.1 方針

エラーが発生した作品はライブラリ一覧のカバー画像上にエラーアイコンを重ねて表示し、ユーザーに修正を促す。作品詳細画面でエラーの具体的な内容を表示する。

### 6.2 検出するエラー

- **メタファイル不正:** JSONパースエラー、必須フィールドの欠落
- **音声ファイル欠損:** メタファイルで定義されたトラックの参照先ファイルが存在しない
- **音声ファイル破損:** 再生時にデコードエラーが発生した場合
- **非対応フォーマット:** サポート外の音声フォーマットのファイルがトラックに含まれる
- **カバー画像欠損:** `coverImage` で指定されたファイルが存在しない（この場合はデフォルトのプレースホルダー画像を表示）

## 7. UI / 画面構成

> UIの詳細デザインは実装済みのフロントエンド（`client/`）が正。`docs/design-system.md` はカラートークン等のデザインシステム規約として参照する。以下は画面構成・機能の要件。

### 7.1 画面一覧

**初期セットアップ画面:** ルートフォルダーが未設定の初回起動時に表示する。ルートフォルダーを指定するとライブラリを構築（フルスキャン）し、完了後にLibraryモードへ移る。ルートフォルダーの再設定中・再設定失敗のときも同じ画面を使う。

**Libraryモード（メイン画面）:** 上段のトップバーとアドレスバー、左ナビ、本体、下部のプレイヤーからなる共通シェル。本体は軸レールと結果面の2要素構成で、list/gridの別によらずレイアウト構造は変わらない。作品を選択したときだけ結果面の右からプレビューがスライドインする。詳細は7.2〜7.7節。

**作品詳細画面:** プレビューの「全画面へ展開」で開く、1作品を画面いっぱいに表示する画面。内容はプレビューと同じ（7.6節）。タグをクリックするとLibraryモードへ移って絞り込む。

**再生中タブ:** 再生中の作品のカバー、トラックリスト、再生操作を表示する画面（5.2節）。

**Filesモード:** ルートフォルダー以下の物理フォルダーをたどって閲覧し、フォルダーや音声ファイルを作品として登録・解除する画面。

**設定モーダル:** ルートフォルダーの変更、スキャンモーダルを開く操作、DLsite一括取得、タグ設定、候補から外したフォルダーの確認・復元。

**スキャンモーダル:** フルスキャンの開始・取消、進捗表示、スキャン結果の確認、未登録候補の登録。タブは「未登録」「要対応」「新規登録済み」「更新された作品」。詳細は8.2節。

### 7.2 共通シェル

画面の上段にトップバーとアドレスバー、左端に左ナビ、下部にプレイヤー（バーまたはポップアップ）を置く。左ナビは本体とプレイヤーの左に縦に通る。

**トップバー:** ブランドマーク＋アプリ名 / 再生中インジケータ（再生状態の点とトラック名、再生対象があるときのみ）/ グローバル検索ボックス（⌘K または Ctrl+K でフォーカス）/ スキャン・通知・設定の3ボタン。検索ボックスはLibraryモードと作品詳細画面にだけ出て、値一覧の軸では無効になる。作品詳細画面で検索を確定（Enter）するとLibraryモードへ移る。スキャン中はスキャンボタンの近くに進捗を表示し、未登録の候補があれば件数をバッジで示す。DLsite一括取得中は、進捗と処理中の作品名、中止ボタンを表示する。

**左ナビ:** Files / Libraryのモード切替、「再生中」ボタン、ユーザーボタン。現在のモードのボタンは強調表示する。「再生中」ボタンは常に有効で、再生中タブを開く。再生対象があるときは再生中を示すバッジを表示する。「履歴」「お気に入り」「ピン留め」のボタンは配置済みだが、無効状態で「近日実装」を示すのみで機能は提供しない（11節「将来候補」参照）。ユーザーボタンは配置のみで、機能は将来候補とする（11節参照）。

**アドレスバー:** 戻る/進む / パンくずナビゲーション / ビュー切替 / 並び替え。Libraryモードではリストとグリッドを切り替える。グリッド表示中は正方形タイルと原寸比率を保つジャスティファイド配置を選び、タイルサイズまたは行高さを調整できる。Filesモードはカラム表示を使う。再生中タブと作品詳細画面では、ビュー切替と並び替えは出さない。

画面の状態（モード、Libraryの軸・絞り込み・検索語、Filesの場所、開いている作品）はURLに反映され、ブラウザーの戻る/進むで辿れる。LibraryとFilesの状態は、別の画面にいる間も保持される（[ADR-0031](adr/0031-app-route-navigation.md)）。

### 7.3 Libraryモード本体

軸レールは常に表示する。軸は「値をブラウズするためのビュー」であり、選択状態そのものは持たない。軸を切り替えても絞り込み（選択中のタグフィルタ）は維持される（[ADR-0012](adr/0012-library-axis-as-value-browse.md)）。

本体は「軸レール（固定幅）」＋「結果面（残りの全幅）」の2要素構成で、list/gridの表示選好によってペイン構造は変わらない。結果面が表示するものは軸の種類で決まる。

- 分類軸（サークル/CVなど）・タグ軸を選んでいて値を選択していない: その軸の値一覧
- それ以外（ビュー軸、スマートフォルダー）、または分類軸・タグ軸で値を選択済み: 作品一覧（list/gridはユーザーの表示選好に常に従う。ナビゲーション状態による表示モードの強制上書きはない）

作品を選択したときだけ結果面の右からプレビューがスライドインし、選択解除でスライドアウトする。値一覧・作品一覧いずれの状態でも、選択されていない間はプレビューは表示しない。

**軸レール:** 作品を並べ替える軸を選ぶ。3グループに区切る。

- ビュー: すべての作品 / 最近再生 / 最近追加 / お気に入り / エラー
- 分類軸: 軸表示がONのprefix定義から動的に生成 ＋ タグ / 追加日（初期設定ではサークル / CV / シリーズ / カテゴリ）
- スマートフォルダー: ユーザー定義の保存クエリ一覧 ＋「新規作成」

各行にアイコン・名前・件数を表示し、選択中の行は強調表示する。最下部にはライブラリ全体の統計（作品数・トラック数・合計時間）を常時表示する。

分類軸・タグ軸の行はホバー約200msでクイックオーバーレイ（検索＋ソート付き値リスト）を開き、素早い乗り換えに使う。クリックまたはフォーカス+Enterで結果面をその軸の値一覧ページへ遷移する。値のクリックは、入口や軸の種類を問わず、選択中のタグをすべて捨てて、その1件だけの絞り込みに置き換える。AND追加の手段は入口ごとに異なる。軸レールのクイックオーバーレイとチップの兄弟値ドロップダウンは、値の行に追加ボタンが現れ、`Ctrl`/`Cmd`+クリックでも追加できる。結果面の値一覧（タイル・行）は、主クリックが置換で、`Ctrl`/`Cmd`+クリックで反転してAND追加になる。結果面上部のチップ列の「＋絞り込み」はAND追加。置き換え選択は結果面を作品一覧へ遷移させ、AND追加は現在の結果面に留まる（[ADR-0013](adr/0013-tag-click-replaces-all.md)）。

**値一覧:** 分類軸・タグ軸を選び、まだ値を選択していないときに結果面へ表示する。

- grid: 代表カバー2×2コラージュタイル＋名前＋件数バッジ
- list: 2×2コラージュ / 名前 / 件数 / 総時間の列を持つ行。名前・件数・総時間の列見出しクリックでソートできる
- 上部にコンテキスト検索ボックス（表示中の値一覧に対するクライアント側絞り込み。軸切替でリセット）を持つ

**作品一覧:** 値選択済みの分類軸・タグ軸、ビュー軸、スマートフォルダーで結果面へ表示する。list/gridはユーザーの表示選好に従う。

- list: 作品行（サムネ＋タイトル/サブ/メタ）を直接列挙する
- grid（作品グリッド）: 正方形タイル（カバーを1:1でトリミングし、設定したタイル幅で並べる）またはジャスティファイド（カバーの縦横比を保ち設定した行高さで各行を敷き詰め）の2方式。表示モード・配置方式・サイズは端末に保存する

タグ軸での複数選択はAND積集合フィルターとして働き、選択中のタグは結果面上部のチップバンドに軸を問わず同じ見た目で並ぶ。

**プレビュー（右）:** 作品を選択したときだけ表示する。

- 通常軸で作品選択時 → リッチ詳細（7.6節）
- スマートフォルダー選択時、作品未選択 → ルールビルダー（7.5節）

### 7.4 検索・フィルタリング・並び替え

**グローバル検索:** トップバーの検索ボックス。タイトル・CV・タグ・RJコードの部分一致。⌘K でフォーカス。

**タグ絞り込み:** 分類軸の値選択もタグ軸の値選択も、選択された時点で同一のタグフィルタ（完全一致AND）へ入る。軸をまたいだ複合絞り込み（例: `cv/藤田茜` かつ `サークル/○○`）が成立する。選択中のフィルタは結果面上部のチップバンドに軸を問わず同じ見た目で並び、ヒット件数をリアルタイム更新する（[ADR-0012](adr/0012-library-axis-as-value-browse.md)）。

**並び替え:** 追加日（新しい/古い順）、タイトル順、再生時間順。将来: 最近再生した順、ランダム順。

検索・絞り込み・ソートは**サーバーサイドで処理**する（クライアントサイドの全件フィルタリングは行わない）。

### 7.5 スマートフォルダー

保存済みのルールセットにより条件に合う作品を動的に抽出する機能。

ルールは `WHERE / AND / AND NOT` の接続詞と「フィールド・演算子・値」で構成する。例: 「長さ ≥ 3時間」「カテゴリ = 環境音 OR ASMR」「タグ ∋ 睡眠用 OR 長時間」「AND NOT タグ ∋ R-15」。

スマートフォルダーを軸レールで選択すると結果面に該当作品を表示し、プレビュー側にルールビルダーを表示する。ルール編集で結果を即時再評価する。

### 7.6 作品詳細（プレビューと作品詳細画面）

プレビューと作品詳細画面は同じ構成で、ヒーロー、タグ、アクション、ステータス警告、トラック表からなる。プレビューには「全画面へ展開」（作品詳細画面を開く）があり、その作品が再生中なら「再生画面へ」（再生中タブを開く）も出る。

- ヒーロー: カバー（クリックで拡大表示）、欠損・エラー時の警告、タイトル、トラック数/総時間、再生・続きから・一時停止の操作
- タグ: 追加・削除ができる。タグのクリックは選択中のタグをそのタグ1件に置き換えてLibraryの作品一覧へ進み、`Ctrl`/`Cmd`+クリックはAND追加になる。作品の選択は外れ、値一覧の軸にいたときは「すべての作品」軸の作品一覧になる。作品詳細画面から押した場合はLibraryモードへ移る（[ADR-0013](adr/0013-tag-click-replaces-all.md)）
- アクション: ブックマーク（ブックマークした作品は軸レールのビュー「お気に入り」に並ぶ）、編集、その他メニュー（作品の情報、関連URLを開く、登録解除）。編集・作品の情報はダイアログで開く
- ステータス警告: ファイル欠損・メタデータエラー時は内容を示し、「Filesで開く」と「登録を解除」を出す。RJコード未検出やDLsite取得失敗・パース失敗の警告には「連携設定を編集」を出す
- トラック表: 番号/タイトル/長さ、レジューム位置

関連作品（同サークル/同タグのカード）、統計（再生回数/累計時間/完聴率）・レーティング（★）・メモは現在提供しない。

### 7.7 プレイヤーバー

プレイヤーの表示（バー、ポップアップ、再生中タブ）は5.2節のとおり。バーとポップアップは、再生対象が読み込まれている間（再生中・一時停止中いずれも含む）、再生中タブ以外の画面で表示される。再生対象が読み込まれていない間はどちらも表示しない。

マルチch同時再生（複数chを重ねて再生する機能）は現在提供せず、対応する操作もUI上に存在しない（将来候補。11節参照）。

ASMR作品の特性を考慮し、シークバーは十分な幅と当たり判定を確保する。±10秒ジャンプ・ループ再生トグルを標準コントロールとして提供する（バーはシーク・音量・前後トラック、ポップアップと再生中タブは±10秒・ループ・再生速度を持つ）。

### 7.8 テーマ

現在はライト基調（紙色トーン）のみを提供する。テーマ切り替えは将来候補で、ダークテーマのトークンは持たない。

## 8. スキャンと初期セットアップ

### 8.1 初期セットアップフロー

1. 初回起動時、ルートフォルダーが未設定であれば初期セットアップ画面を表示する
2. ユーザーがルートフォルダーを指定する
3. ルートフォルダー以下を再帰スキャンしてライブラリを構築する（自動実行）。進捗は画面に表示する
4. メタファイルが見つかった作品はDBに登録/更新する
5. メタファイルがなく音声ファイルを含むフォルダーは、未登録の候補として保持する。この時点でメタファイルは作らない（3.5項）
6. 構築が終わるとLibraryモードへ移る。未登録の候補はスキャンモーダルの「未登録」タブで確認し、登録する

ルートフォルダーを変更すると、新しいルートの配下にない作品をライブラリから外し、フルスキャンでライブラリを作り直す。作り直している間は初期セットアップ画面と同じ画面を表示し、他の操作は受け付けない（[ADR-0029](adr/0029-root-reconfiguration-workflow.md)）。

### 8.2 スキャンのトリガーと実行モデル

**現在のスキャントリガー:**

- **手動トリガー:** トップバーのスキャンボタン、または設定モーダルの「スキャン」ボタンからスキャンモーダルを開く。即時実行はせず、モーダル内でフルスキャンの開始・取消、結果の確認、未登録候補の登録を行う。設定モーダルには前回スキャン日時も表示する
- **初回起動時・ルートフォルダー変更時:** ルートフォルダーの設定が済むと、自動でフルスキャンを実行する

**未登録候補と新規作品:** スキャンで見つかったメタファイルのないフォルダーは、スキャンモーダルの「未登録」タブに候補として並ぶ。候補は選んで登録でき、登録が済むと「新規登録済み」タブに移る。登録した作品のタイトルはフォルダー名から付き、「新規登録済み」タブで直せる。登録した作品と、スキャンで新たに見つかった作品は、DLsite一括取得のキューに積まれ、進捗は別のチャンネルで通知する。

ファイル監視（watcherによるリアルタイム検知）、アプリ起動時の自動スキャン、差分スキャンは将来候補とする。

**スキャン中のUI:** スキャンはバックグラウンドで実行し、スキャン中もライブラリの閲覧・再生は可能とする。モーダルを閉じてもスキャンは継続する。完了したら、モーダルが閉じていれば結果のサマリー（登録・新規・エラー・行方不明の件数）をトースト通知で表示し、要対応の項目があれば「要対応を見る」から該当タブへ進める。

スキャンの進捗は、サーバーが持つ現在の状態を画面に同期する形で配信する。画面にはスキャン実行中だけ接続し、進行フェーズと件数を反映する。接続が切れて再接続したときは、その時点の状態（実行中なら現在の進捗、終わっていれば結果）で表示を続け、切断中の途中経過は再生しない。終了時は、画面が結果を取り直して確定してから完了を扱うため、完了通知を取りこぼさない（[ADR-0030](adr/0030-job-progress-sse-current-state.md)）。

### 8.3 再スキャン

再スキャンではメタファイル内の作品IDで突合し、フォルダーの移動・リネーム後も同一作品として物理パスを更新する。登録済みの作品IDが見つからない場合は「行方不明」ステータスにする。同じ作品IDを持つメタファイルが複数見つかった場合は、routine scan は自動再採番せず `identity_conflict` として診断・表示する（[ADR-0017](adr/0017-meta-source-projection-and-work-identity.md)）。

## 9. リモートストリーミング

### 9.1 概要

PC上のローカル API サーバー（Hono + Bun）を常駐させ、iPadなど別端末のWebブラウザからLAN経由で音声をストリーミング再生する。基本的なローカルサーバー化（`server/`）は実装済み。

### 9.2 アーキテクチャ

```
[PC (Hono サーバー)]                   [iPad等 (Webブラウザ)]
┌──────────────────────┐               ┌──────────────────┐
│  TS バックエンド       │◄── HTTP ──────│  Web UI (React)  │
│  ┌─────────────────┐ │               └──────────────────┘
│  │ core / adapters │ │  ← ローカルUIとリモートUIで共有
│  │ (Hono routes)   │ │
│  │ SQLite           │ │
│  └─────────────────┘ │
└──────────────────────┘
```

### 9.3 今後の拡張項目

- 認証付きリモートアクセス（LAN外からのアクセス制限）
- リモート公開時の配信方式とアクセス制御

## 10. データのポータビリティ

- メタファイルが作品フォルダーと共に移動するため、フォルダーごとのコピーで情報が維持される
- DB + ルートフォルダーのコピーで別環境への移行が可能
- タグやメタデータの一括エクスポート/インポート機能は将来検討

## 11. 現在の保証範囲と将来候補

### 現在保証する仕様

- Libraryモードはリスト表示とグリッド表示を持ち、グリッドは正方形とジャスティファイドの2方式に対応する
- 検索、タグAND絞り込み、軸ファセット、ソート、ページング、スマートフォルダーの評価はAPIサーバーで処理する
- スキャン進捗とDLsite一括取得進捗を、現在の状態の同期として通知する（途中経過は再生しない。ADR-0030）
- 音声配信はHTTP Rangeに対応し、プレイヤーはレジューム、再生速度変更、L/R入れ替え、A-Bリピート、OSのメディアコントロール連携を提供する
- ブックマークと最終再生日時はSQLiteに保存する
- `mimimilli.json` の編集、スキャン、未登録候補とFilesからの作品登録（フォルダー形式・単一ファイル形式）、DLsite情報取得、カバーのサムネイル生成、Filesモードによる物理フォルダー閲覧を提供する
