# ADR-0013: タグ値の通常クリックは完全置換とし、AND 追加は可視のボタンで行う

- ステータス: 承認
- 日付: 2026-08-07
- 関連: [ADR-0012](0012-library-axis-as-value-browse.md)（本ADRで §7 を一部改訂）

## 文脈

ADR-0012 §7 で「値選択の既定は入口ごとに異なり、どの入口でも `Ctrl`+クリックで反転する」と定め、TASK-182 で実装した。このうち「置き換え」は同一の `tagFilterGroupKey`（組み込み軸は軸ごと、prefix 付き実タグは prefix ごと、フラットタグは全体で1つ）に属するタグだけを外して追加する、グループ内置換として実装された。

この結果、同じ通常クリックが対象タグの prefix によって別の意味を持つ。`癒し系` を選んだ状態で `朗読` をクリックすると置き換わるが、`cv/霧島レイ` をクリックすると既存が残って AND で積み上がる。prefix が同じかどうかは画面上に表示されておらず、ユーザーには結果を予測できない。実測でも、2つの操作は見た目上まったく同じクリックでありながら、一方は1件に絞り込まれ、他方は0件になった。

加えて、可視の AND 追加ボタンは結果面の値一覧（タイル・行）にしか無い。軸レールのクイックオーバーレイとチップの兄弟値ドロップダウンでは AND 追加の手段が `Ctrl`+クリックだけで、画面上に手がかりが存在しない。これは TASK-182 の起票時点からの意図的な書き分けだったが、「条件を積む」という主要操作が入口によって発見できないという偏りを生んでいる。

問題は AND 絞り込みができることではなく、同じ操作の意味が不可視の内部概念（prefix グループ）によって変わること、および意味を選ぶ手段が入口ごとに欠けていることにある。

## 決定

タグ値の通常クリックは、対象タグの prefix や軸に関係なく常に完全置換とする。選択中のタグをすべて捨て、クリックしたタグ1つだけの絞り込みにする。

AND 追加は、通常クリックとは別の明示的な操作でのみ行う。`Ctrl`+クリックに加えて、値を選べるすべての入口に可視の追加ボタンを置く。ボタンは値一覧と同じくホバー・フォーカス時に行内へ現れる形とし、アクセシブル名は「〇〇を AND 追加」で統一する。

入口ごとの既定は次のとおりとする。既定が置き換えの入口には追加ボタンを置き、既定が AND 追加の入口には置かない。同じ操作を二重に提供しないためである。

| 入口                           | 通常クリック | 追加ボタン |
| ------------------------------ | ------------ | ---------- |
| 軸レールのクイックオーバーレイ | 完全置換     | あり       |
| チップの兄弟値ドロップダウン   | 完全置換     | あり       |
| 結果面の値一覧（タイル・行）   | 完全置換     | あり       |
| チップ列の「＋絞り込み」       | AND 追加     | なし       |
| 作品詳細のタグクリック         | 完全置換     | なし       |

`Ctrl`+クリックによる既定動作の反転は全入口で維持する。

ADR-0012 §8 の「置き換えは結果面を作品一覧へ進め、AND 追加は現在地に留まる」は変更しない。置き換えの範囲が広がっても、操作の意味と行き先を一致させるという原則は同じである。

ADR-0012 §4 の year 軸の単一選択も維持する。異なる2年の AND は恒常的に0件になるため、AND 追加の経路では同じ組み込み軸の既存選択を先に外す扱いを残す。これは通常クリックの置き換え範囲とは独立した制約である。

## ADR-0012 からの改訂点

§7 の「クイックオーバーレイの選択は置き換え既定」という記述自体は維持されるが、そこでいう「置き換え」の意味がグループ内置換から完全置換に変わる。あわせて「可視の追加ボタンは結果面の値一覧にのみ用意する」という書き分けを廃止し、置き換え既定のすべての入口に追加ボタンを置く。

## 帰結

- `tagFilterGroupKey` と `computeReplacedTags`（`client/src/features/library/model/libraryPresentation.ts`）は用途がなくなり削除対象になる。置き換えは選択配列を `[tag]` に差し替えるだけの操作になる
- `replaceLibraryTagAtom` と `selectSoleLibraryTagAtom` はタグ配列への書き込み内容が一致するが、軸遷移の規則（前者は works 種の結果面を維持、後者は常に tag 軸へ遷移）が異なるため統合しない
- `AxisValueQuickList` の値行は、行全体を1つの `button` とする現在の構造から、値一覧と同じ「`div` の中に主選択ボタンと追加ボタンを並べる」構造へ変える。button の入れ子を避けるためであり、仮想化の固定行高は変えない
- 同一 prefix 内の複数値を AND で絞り込む操作（`cv/A` かつ `cv/B` など）は引き続き可能で、追加ボタンまたは `Ctrl`+クリックで行う
- 通常クリックだけを使う限り絞り込みが1タグを超えて積み上がらないため、意図せず0件になる経路が減る
