# ADR-0042: ドラッグ＆ドロップの基盤に Pragmatic drag and drop を使う

- ステータス: 承認
- 日付: 2026-11-22
- 関連: [ADR-0041](0041-library-sidebar-shell-navigation.md)（サイドバーの編集）、[ADR-0040](0040-smart-folder-condition-tree.md)（並び順の保存）、[ADR-0006](0006-mobile-ui-strategy.md)（モバイルに管理機能を持ち込まない）

## 文脈

[ADR-0041](0041-library-sidebar-shell-navigation.md) のサイドバーでは、スマートフォルダーをドラッグで並べ替える。client には今、ドラッグ＆ドロップの実装が1つも無い（`draggable`・`dataTransfer` の使用なし）。外部ファイルのドロップも無い。

サイドバーの並べ替えだけなら素書きでも書けるが、次の段階には作品をサイドバーの行へドロップする操作、複数選択した作品のドラッグ、エクスプローラーからのファイルのドロップが控えている。作品一覧は `@tanstack/react-virtual` で仮想化していて、ドラッグ中に行が出入りする。最初に入れる基盤は、これらにそのまま使えるものにしたい。

候補は Atlassian の Pragmatic drag and drop、dnd-kit、ネイティブの HTML5 ドラッグ＆ドロップの素書きの3つだった。

## 決定

ドラッグ＆ドロップの基盤に Pragmatic drag and drop（`@atlaskit/pragmatic-drag-and-drop`）を使う。

今回の用途はサイドバーの中の並べ替えだけにする。

- 行の上半分・下半分で前後を決めるのに、hitbox パッケージの list-item（`attachInstruction`・`extractInstruction` の `reorder-before`・`reorder-after`）を使う
- ドロップ後は全件の順序を並べ替え API に送る（[ADR-0040](0040-smart-folder-condition-tree.md)）
- ドラッグ中は、グループ分けを持つ行のクイックオーバーレイを出さない
- モバイルではドラッグ＆ドロップを出さない（[ADR-0006](0006-mobile-ui-strategy.md) の、管理機能を持ち込まない方針に従う）

選んだ理由は次のとおり。

- ネイティブのドラッグ＆ドロップの上に乗っていて、外部ファイルのドロップ（`dropTargetForExternal`・`monitorForExternal`）を同じ仕組みで受けられる。dnd-kit はファイルのドロップを扱わない
- ドロップ先の登録は要素ごとの命令的な API で、ドラッグ中に DOM が変わってもよい。仮想化で行が出入りしても、登録は effect の後始末で外れる
- 作品を行へ落とす操作（`combine`）と行の並べ替え（`reorder-before`・`reorder-after`）を同じ行の上で両立でき、ドラッグ元の種類で出し分けられる
- 複数の作品をドラッグするときは、`setCustomNativeDragPreview` で「n件」の束をプレビューとして描ける
- 自動スクロール（auto-scroll パッケージ）を、作品一覧のスクロール要素とサイドバーの両方に付けられる
- 本体が小さい（公式の比較で約4.7kB gzip、dnd-kit の sortable 一式で約27kB。Atlassian 自身の数字）

採らなかったもの:

| 候補               | 判断                                                                                                                                                                                                                             |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| dnd-kit            | 不採用。外部ファイルのドロップを扱わない。新しい `@dnd-kit/react` は 0.x で、sortable は全項目が DOM にある前提に寄っている。ドラッグ中に項目が滑らかにずれる見た目とキーボード操作の標準対応は dnd-kit の方が上                 |
| ネイティブの素書き | 不採用。`dragenter`・`dragleave` の子要素での誤発火、`dragover` での `preventDefault`、`dragend` が来ない場合、自動スクロール、Android・iOS の癖を自前で吸収することになる。Pragmatic drag and drop の中身はほぼこの安全化である |

## 帰結

- サイドバーの並べ替えから始めて、次の段階の作品のドラッグ＆ドロップ、複数選択のドラッグ、外部ファイルのドロップを同じ基盤の上に足せる
- ドラッグ中の見た目はブラウザのドラッグイメージ（半透明のスナップショット）になる。要素そのものが滑らかに動く表現はできない。ドロップ位置の線は自前で描く
- キーボードでの並べ替えは基盤に無い。代わりの操作が要るなら、メニューやボタンで別に用意する
- パッケージは `@atlaskit/*` の複数（本体・hitbox・必要なら auto-scroll）に分かれる。保守の状況と最新版の公開日は、導入するときに npm で確かめる
- ネイティブのドラッグ＆ドロップなので、Windows の Chrome・Edge でのドラッグイメージは実機で確かめる
- 作品のドラッグ、右クリックメニュー、複数選択、外部ファイルのドロップは今回の範囲に入れない。複数選択の状態設計はドラッグより先に要る
