# ADR-0012: ライブラリの軸は値ブラウズのビュー、値の選択はタグフィルタとする

- ステータス: 承認
- 日付: 2026-08-03
- 関連: [ADR-0005](0005-tags-as-sole-attribute.md)（本ADRで一部改訂）、backlog DRAFT-50、TASK-178〜183

## 文脈

ADR-0005 で「CV もサークルもタグの1つ」というデータモデルは実現したが、UI 側は軸ごとに別々の操作機構を持ったままだった。

- facet 軸（cv・サークル等）は「ドリル」という専用の選択状態（`drillValue`）を持ち、選択後は作品一覧へ遷移する
- tag 軸だけがチェックボックスによる複数選択 AND フィルタを持ち、他軸と複合できない
- ドリル中は `showGrid = canShowWorksGrid && (isDrilledFacet || viewMode === "grid")` によってユーザーの list/grid 設定が無視され、強制的にグリッドになる
- 中間カラム（`ContentColumn`、幅300px固定）が「値の一覧」と「作品のリスト」という異なる役割を兼ねており、軸を切り替えるたびにレイアウト構造そのものが変わる

結果として、リストモードを選んでいても軸を触ると勝手にグリッドになる、選択状態が軸ごとに非対称でCVとサークルを同時に絞り込めない、といった一貫性の欠落が生じていた。原因はデータモデルではなく、UI がナビゲーション状態（どの軸を見ているか）と表示設定（list/grid）と絞り込み状態（何で絞っているか）の3つを1本の分岐に混ぜていたことにある。

## 決定

この3つを分離し、それぞれ独立した状態として扱う。

### 1. 軸は「値をブラウズするためのビュー」であり、選択状態を持たない

軸レールの選択は「いま結果面に何の値一覧を出しているか」だけを表す。ドリル機構（`drillValue` / `isDrilledFacet`）は廃止する。軸を切り替えても絞り込みは維持される。

### 2. 値の選択はすべてタグフィルタに一本化する

facet 軸の値も tag 軸の値も、選択された時点で同じタグフィルタ（完全一致 AND）へ入る。軸をまたいだ複合絞り込み（例: `cv/藤田茜` かつ `サークル/○○`）が成立する。選択されたフィルタは結果面上部のチップ列に、軸を問わず同じ見た目で並ぶ。

`year` 軸のようなタグ由来でない組み込み軸も、フィルタとしては同じ機構に載せる。URL 上は `tags=@year/2024` のように擬似タグとして表現し、フィルタ解釈層で組み込み軸として解決する（`year` は実体としてタグではなく `addedAt` の年照合だが、URL 契約・チップ表示・解除操作はタグと完全に同一の経路を通す）。組み込み軸ごとに別のクエリパラメータを設けるとチップとの対応が二重系になるため採らない。

先頭の `@` は組み込み軸の擬似タグ専用の予約文字とし、実タグが `@` で始まることをタグ検証で拒否する。ADR-0005 は `year/2025` をユーザー定義タグの例として明示しており、予約なしでは実タグと擬似タグが衝突して実タグ `year/2025` の絞り込みが `addedAt` の年照合に化ける。予約文字による分離は、この曖昧さを型と検証で閉じるための最小の措置である。

組み込み軸のうち `year` は同時に1つの値しか選択できない（新しい年を選ぶと前の選択を置き換える）。異なる2年の AND は常に0件になるため、複数選択を許すとチップ表示と結果が恒常的に矛盾する。

### 3. 表示設定（list/grid・タイルサイズ）をシステムが上書きしない

`showGrid` のようなナビゲーション状態由来の表示モード上書き分岐は全廃する。値一覧・作品一覧のいずれも、常にユーザーの `libraryViewMode` 設定に従う。レイアウトは `[軸レール][結果面（全幅）]` に固定し、作品を選択したときだけプレビューがスライドインする。中間カラムは廃止する。

### 4. 「概要」（axis-landing）を廃止し、発見ダッシュボードは独立したホームビューにする

軸を選んだだけの状態は「その軸の値一覧」を出すため、値未選択時のプレースホルダーとしての概要面は不要になる。`DiscoveryDashboard` は軸レール上の「ホーム」ビューとして独立させ、軸選択とは無関係に到達できるようにする。

### 5. 値一覧はデータ列を持つ一覧として表示する

- grid: 代表カバー2×2コラージュタイル＋名前＋件数バッジ
- list: 2×2コラージュ(32px) / 名前 / 件数 / 総時間 の列を持つ行。名前・件数・総時間の列見出しクリックでソート可能

このため軸値ファセットの契約（`AxisFacetItem`）を `{ value, count }` から総再生時間・代表カバーを含む形へ拡張する。値一覧のソートは表示名の単純比較に固定せず、ソートキーを注入できる形で実装する（将来の読み仮名メタデータ導入に備える。DRAFT-49）。

### 6. 検索は2系統を明確に分ける

- 全体検索（`librarySearchQueryAtom`、URL の `q=`）: 作品の検索。従来どおり
- コンテキスト検索: 値一覧・オーバーレイ内の絞り込みボックス。表示中の値リストに対するクライアント側の絞り込みで、URL には載せず軸切り替えでリセットする

### 7. 軸レールはホバーとクリックで役割を分ける

CV・サークルは数百規模になりうるため、素早い乗り換えとじっくり探す操作を分離する。

- ホバー約200ms: クイックオーバーレイ（検索＋ソート付き値リスト）。選択は置き換え既定
- クリック / フォーカス+Enter: 結果面をその軸の値一覧ページへ遷移。オーバーレイ表示中のクリックも遷移
- フォーカス中の `ArrowRight`: オーバーレイを開く。`Escape` で閉じてレールへフォーカス復帰

追加（AND）と置き換えの既定は入口ごとに異なるが、どの入口でも `Ctrl`+クリックで既定動作を反転する。

## ADR-0005 からの改訂点

ADR-0005 §6「軸ドリル・タグ AND/OR 絞り込み」のうち「軸ドリル」という独立した絞り込み経路は本ADRで廃止し、タグ AND 絞り込みへ統合される。一致セマンティクス（完全一致）自体は変更しない。ADR-0005 追記（2026-07-31）の「`tag` 軸はチェックボックスの複数選択 AND、個別 prefix 軸は単一ドリルで役割が異なる」という併存の整理も、本ADRで「両者は同一のフィルタ機構であり、軸は見る対象が違うだけ」に置き換わる。

## 帰結

- `libraryPresentation.ts` の `showGrid` / `canShowWorksGrid` / `isDrilledFacet`、`drillValueAtom`、`drillIntoAtom` / `drillBackAtom`、`ContentColumn.tsx`、`preview/AxisLanding.tsx` が廃止対象になる
- URL 契約が変わる。`/library/:axis/:drillValue` の drillValue セグメントは廃止し、絞り込みは全軸で `tags=` クエリに載る（tag 軸限定の制約を外す）
- パンくずは「ライブラリ > 軸名」までを表し、絞り込みはチップ列が唯一の表現とする（責務の重複を作らない。DRAFT-41）
- ソートは UI が単一系、state が二重。ソートメニューと list の列見出しクリックは同一のソート状態への別入口であって独立した系ではないが、値一覧のソート状態と作品一覧のソート状態は別々に保持し、UI が結果面の内容に応じてどちらへ接続するかを切り替える。1つの state を共有すると、総時間ソート中に値を選択したとき作品一覧に無効なソートキーが渡って壊れる
- 軸値ごとの総時間・代表カバーは SQL の集計拡張が必要になり、値の数に比例したコストが乗る。大規模データでの実測は実装タスクの受け入れ条件に含める
