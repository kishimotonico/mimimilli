# ADR-0009: 一般アイコンにlucide-reactを採用する

- ステータス: 承認
- 日付: 2026-07-26
- 関連: backlog TASK-104、[design-system.md](../design-system.md)

## 文脈

アイコンは `client/src/shared/ui/Icon.tsx` の `I` レジストリに47個定義し、34ファイル・118箇所から `I.xxx` で参照している。実装は24×24 viewBox、stroke 1.5、round cap/join、`currentColor`、`aria-hidden="true"` 固定の自作SVGで、意味は `IconButton` 側の `aria-label` が担いSVGは装飾として扱う。

`IconButton` は箱26/30/38px・アイコン14/16/20pxのサイズ契約を持つ。実測では `size` 指定の40箇所が13px以下で、14px以上より多い。stroke 1.5のSVGを9px相当まで縮小表示すると実効線幅が約0.56pxまで細り、視認性が崩れる。自作SVGは `strokeWidth` を外部から補正する仕組みを持たず、この問題への対処手段がない。

既存47個のうち少なくとも `search` はlucideの`Search`とパス座標（`-4.3`など）まで一致しており、出自を記録せずに流用したものが混在している疑いがある。リポジトリにLICENSE・NOTICE・third-party noticeはなく、README のライセンス欄はPrivateのみである。

## 決定

一般アイコン（検索・再生・メディア種別・ナビゲーション等、汎用的な意匠でよいもの）はlucide-reactから取得する。呼び出し側からlucide-reactを直接importすることは禁止し、必ず `I` レジストリ経由にする。stroke幅・`currentColor`・`aria-hidden`はアダプタ層（`Icon.tsx`）で固定し、lucide固有propsを呼び出し側へ漏らさない。サイズは`IconButton`のサイズ契約に従い、呼び出し側で独自の数値を散らさない。

製品固有アイコン（`ratio11`、`gridJustified`、`loopOne`、`swapLR`、プレイヤー系の塗り表現など、一般カタログに対応する意匠がないもの）は自作を維持し、同じ `I` レジストリへ追加する。

lucide-reactを選んだ理由は次の通り。

- 小サイズで`strokeWidth`による線幅補正ができる。9px表示でのstroke細りという実測の課題に対する直接の解決手段になる
- 通常のReact SVGコンポーネントとして扱え、既存の`Svg`ラッパーと同じ組み込み方ができる
- 現行47個はoutline中心の意匠で、filledカタログの充実度をこのアプリは強く必要としない
- `I`をアダプタ層として維持すれば、呼び出し側34ファイルは無変更のまま移行できる

却下した候補は次の通り。

| 候補                      | 判断                                                                                                                                                                                                                                                                                                                                                |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@tabler/icons-react`     | 設計上の誤りではなく次点。カタログ5900個超とfilledの多さはこのアプリでは十分に活用されない。現行アイコンとの対応率や9〜13pxでの見た目がlucideより良ければ逆転しうる                                                                                                                                                                                 |
| `reicon-react`            | 24×24グリッド・outline 1.5px・Outline/Filledの2ウェイトという点で仕様は最も近い。ただしOutlineがstrokeでなく塗りパスで表現されており、`strokeWidth` propが無言で効かない（実装はstroke-width属性への正規表現置換で、置換対象が存在しない）。小サイズで細すぎた場合の修正手段がない。npm公開が2026-05-03と運用実績が短く、単独メンテナ、週間DL 8,843 |
| Its Hover（itshover.com） | hoverアニメーション付きのcopy-paste配布で、基盤セットには使わない。`size` propがなくclassNameベース、カタログ186個程度、shadcn/Next.js前提。アニメーションは13px以下では判別できず、このアプリのアイコンは大半がそのサイズ帯。将来、数個の主要操作に演出を加えたい場合は`I`に混ぜず明示的なアニメーション付きコンポーネントとして別枠で扱う         |
| `@heroicons/react`        | outlineがstroke 1.5で数値は一致するが、カタログが約300個でメディア・グリッドレイアウト・ソート系が薄い。`size` propがなく現状の契約に合わない                                                                                                                                                                                                       |
| `@iconify/react`          | ランタイムでネットワークから取得しない構成は可能だが、データの明示登録とセットごとの意匠・ライセンス管理が必要で、47個規模には構成コストが重い                                                                                                                                                                                                      |
| 自作維持                  | 機能・保守性だけを見れば今すぐ入れる必要はない。ただし既存SVGに出自の記録がなく、`Icon.tsx`の`search`はlucideの`Search`とパス座標（`-4.3`）まで一致しているため、出自が明確な実装へ置き換える動機がある                                                                                                                                             |

## 帰結

- 既存SVGの出自・ライセンス表記は未整理のまま残る。47個を独自作成/ライブラリ由来/不明に分類し、third-party noticeを配布物へ含める作業は別途必要になる
- lucide由来へ置き換えても、自作として残すアイコンの過去の出自が自動的に明確になるわけではない
- アダプタ層があっても撤退コストはゼロではない。`package.json`とlockfile、ライセンス表記、47個の再マッピング、visual snapshotの再確認が伴う。採用直後はコミット単位で安く戻せるが、運用後の撤退は1ファイルでは終わらない
- 9〜13pxでの実際の視認性は未検証。移行時に確認する
