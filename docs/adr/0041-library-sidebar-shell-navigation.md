# ADR-0041: ライブラリを本体にしてサイドバーを1本にし、再生中を重なる層にする

- ステータス: 承認
- 日付: 2026-11-22
- 関連: [ADR-0040](0040-smart-folder-condition-tree.md)（スマートフォルダーのモデルと評価）、[ADR-0031](0031-app-route-navigation.md)（AppRoute と URL 形式を本ADRで改訂）、[ADR-0013](0013-tag-click-replaces-all.md)（タグクリックの行き先・兄弟値ドロップダウンを本ADRで改訂）、[ADR-0012](0012-library-axis-as-value-browse.md)（決定7を本ADRで改訂）、[ADR-0016](0016-view-axis-consolidation.md)（ライブラリ統計の置き場所）、[ADR-0026](0026-value-list-as-global-entry.md)（値一覧でチップと検索語を効かせない前提と、値一覧の Ctrl+クリックを本ADRで廃止）、[ADR-0006](0006-mobile-ui-strategy.md)（ナビゲーション形態の前提を本ADRで改訂）、[ADR-0042](0042-pragmatic-drag-and-drop.md)（サイドバーの並べ替え）、backlog DRAFT-61

## 文脈

左側のナビゲーションは2段になっている。縦のアイコン列（`client/src/app/ui/LeftNav.tsx`）でファイル・ライブラリ・再生中を切り替え、ライブラリの中ではさらに軸レール（`client/src/features/library/ui/AxisColumn.tsx`）でビュー・分類軸・スマートフォルダーを選ぶ。アイコン列のうち履歴・お気に入り・ピン留めは「近日実装」のまま無効になっている。

ファイル・ライブラリ・再生中は、AppRoute の `mode` として同格に並んでいる（[ADR-0031](0031-app-route-navigation.md)）。再生中を開くと下の画面から離れ、`/now-playing` という別の URL になる。再生バー（bar モード）には再生中画面への直接の入口が無く、ポップアップを開いてから ⤢ を押す2手が要る。

[ADR-0040](0040-smart-folder-condition-tree.md) でライブラリの行がすべてスマートフォルダーになり、軸レールとビューの区別がなくなった。スマートフォルダーの定義はサーバーから来るので、URL だけでは「値一覧か作品一覧か」「`group` の値が何を指すか」が決まらない。今の parse は軸 ID だけから値一覧かどうかを決めている（`client/src/entities/navigation/model/navigationUrl.ts`）。

## 決定

### 全体の構成

ライブラリをアプリの本体にする。ファイルはトップバーの道具、再生中は今の画面に重なる層にする。

| 画面                           | サイドバー                                                       | 再生バー                           | アドレスバー                                                                                             | 戻り方                                                             |
| ------------------------------ | ---------------------------------------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| ライブラリ（作品一覧・値一覧） | 出す（隠していれば隠したまま）                                   | 再生中なら出す                     | 左端に開閉ボタン、戻る・進む、パンくず（ライブラリ › スマートフォルダー › 値）、表示形式、ソートメニュー | ブラウザの履歴                                                     |
| 作品詳細                       | 出す。選択中の行は元のスマートフォルダーで、押すと元の一覧へ戻る | 出す                               | 開閉ボタン、戻る・進む、パンくず。表示形式と並び順は出さない                                             | ブラウザの履歴（直前のライブラリ）                                 |
| ファイル                       | 出さない（全幅のカラム表示）                                     | 出す                               | 開閉ボタンは出さない。トップバーのファイルボタンが点灯                                                   | ファイルボタンをもう一度押す、ライブラリへ戻る操作、ブラウザの戻る |
| 再生中の層                     | 層の下に隠れる（状態は変えない）                                 | 出さない（層が自分の操作部を持つ） | 層が覆う。トップバーは残す                                                                               | 閉じるボタン、Esc、ブラウザの戻る                                  |

`LeftNav` と `AxisColumn` はなくし、サイドバー1本にする。ファイルから戻ったときと、作品詳細で選択中の行を押したときは、保持しているライブラリの状態（スマートフォルダー・グループの値・チップ・検索語・今の並び・ランダムの seed）をそのまま使う。

### サイドバー

- 節の見出しは「ライブラリ」1つ。次の段階で「プレイリスト」の節を足すが、今は見出しも出さない
- 画面には「スマートフォルダー」「項目」のような総称を出さず、動詞と行の名前で書く。文書とコードでは「スマートフォルダー」と呼ぶ
- 隠す・出すだけを持つ。アドレスバー左端のボタンと Ctrl+B で切り替え、状態は端末に保存する。画面幅では自動で切り替えない。作品詳細でも同じ状態を使う
- 将来「アイコンだけ＋ホバーで詳細」に広げる余地は残す。Ctrl+B は将来のキーコンフィグで変えられるようにする可能性がある
- 幅の変更は今回は入れない
- 最下部のライブラリ統計（作品数・トラック数・合計時間。[ADR-0016](0016-view-axis-consolidation.md)）は残す
- 件数は、条件が空のスマートフォルダー（すべて・ランダム）とグループ分けを持つものには出さない。「最近再生」には出す。「エラー」（条件が `hasError` だけで、グループ分けを持たないもの）は件数を赤い丸で出し、0件でも行は出したまま件数だけを出さない（[ADR-0040](0040-smart-folder-condition-tree.md)）

見出しの ＋ からは、今の検索の保存（絞り込みが無いときは今のスマートフォルダーの複製）、グループ分けの追加、既定から追加ができる。

見出しの編集の操作で編集の状態に入り、ドラッグで並べ替え（[ADR-0042](0042-pragmatic-drag-and-drop.md)）、名前・グループ分け・既定の並び・グループ分けのソートの変更、削除ができる。並べ替えの保存中は次のドラッグを受け付けない。編集のダイアログでは、条件をルート直下の子ごとに × で外せる。既定のスマートフォルダーも自作のものと同じに編集できる。「すべて」だけは既定の並びと位置しか変えられない（[ADR-0040](0040-smart-folder-condition-tree.md)）。削除はトーストから取り消せる（作成の口に同じ ID・位置で送り直す）。

グループ分けを持つ行は、今の分類軸と同じくホバーでクイックオーバーレイを出す。値の主クリックはその値の作品一覧（`/library/by-cv?group=値`）へ進み、追加ボタンはチップを足す（行き先は後述）。ドラッグ中はオーバーレイを出さない。

### ソートメニューと保存の操作

ソートメニューはアドレスバーに置き、今の並びを変える。結果面が作品一覧のときは作品の並び（9種）、値一覧のときは値の並び（8種。向きは ID に含まれる）を変え、どちらもグリッド表示でも変えられる。今の並びが解決後の既定の並び（[ADR-0040](0040-smart-folder-condition-tree.md)）から外れているときだけ、メニューに「このソートを既定にする」を出し、作品の並びなら `sort`、値の並びなら `group_sort` に保存する。値一覧の列見出しのクリックは、メニューと同じ今の値の並びを変える。サイドバーのクイックオーバーレイは、そのスマートフォルダーの保存済みの値の並びで開く。パンくずの値のポップオーバーは、開いているスマートフォルダーの今の値の並び（route の `groupSort`、無ければ保存済み）で開く。値と件数の母集団は場所で分ける。値一覧とパンくずの値のポップオーバーは、今のチップと検索語をかけた値と件数を出す（ポップオーバーから兄弟の値へ移ってもチップと検索語は保たれ、値一覧へ戻ったときと同じ集合になる）。サイドバーのクイックオーバーレイは絞り込みなしで出す（そこから入るとチップと検索語は消えるため）。どちらも中の列見出しのクリックは開いている間だけの一時状態で、route にも定義にも書かない。

- 「『すべて』と同じ」のスマートフォルダーで押すと、そのスマートフォルダーだけが自分の並びを持つ。継承に戻すのは編集のダイアログで「『すべて』と同じ」を選ぶ
- 「すべて」で押すと、「『すべて』と同じ」のスマートフォルダー全部の並びも変わる

メニューで変えるたびに保存はしない。保存すると「ランダム」や「最近再生」が性格を失ったまま保存されるからである。

検索の保存の操作は、常設のチップ列の右端に置く。そのために行は増やさない。

| 状態                                                                                                   | 出す操作           |
| ------------------------------------------------------------------------------------------------------ | ------------------ |
| 保存先が無い絞り込み（「すべて」か、グループ分けを持つスマートフォルダーで、値・チップ・検索語がある） | 検索を保存         |
| 「すべて」以外でグループ分けを持たないスマートフォルダーで、チップを足したか並びを変えた（※）          | 上書き、別名で保存 |
| 「すべて」以外でグループ分けを持たないスマートフォルダーで、検索語だけを入れた                         | 検索を保存         |

- ※「並びを変えた」は、今の並びが解決後の既定の並びと異なることを指す（メニューの「このソートを既定にする」と同じ判定）。route に今の並びがあっても、既定と同じなら変えていない
- 上書きは、「すべて」以外でグループ分けを持たないスマートフォルダーにだけ出す。既定から入れたものにも出す
- 上書きだけは、成功のトーストの「元に戻す」で上書き前の定義へ戻せる。新しく保存したものは削除（これもトーストから元に戻せる）で戻す
- 保存の中身は [ADR-0040](0040-smart-folder-condition-tree.md) の「条件の編集」に従う

保存・上書き・削除のあとの行き先は次のとおりにする（await をはさむときの規則は「再生中の層」の節の最後）。新規保存（検索を保存・別名で保存・＋から作る）は、作ったスマートフォルダーをサイドバーから入るときと同じく絞り込みなしで開く（履歴を積む）。上書きは、同じスマートフォルダーを絞り込みなしで開き直す（置き換え）。保存した絞り込みが条件に入ったので、チップと検索語は消える。上書き前に戻すのはトーストの「元に戻す」で、ブラウザの戻るではない。削除で開いているスマートフォルダーや保持しているライブラリの行が消えたときは、消えたスマートフォルダーからの退避の補正（後述）で「すべて」へ移る。このときチップ・検索語・今の並びは残る。

### スマートフォルダーの切り替えと検索の行き先

スマートフォルダーを切り替えると、チップと検索語は消える。スマートフォルダーは条件の束なので持ち越さない。0件になったときは「すべて」で探す操作を出し、同じチップと検索語のまま「すべて」へ移れるようにする。

チップと検索語は、作品一覧でも値一覧でも同じように効く。値一覧でチップを足したり検索したりすると、同じスマートフォルダーの値一覧のまま、値と件数が絞り込み後のものになる（「CV別」に「癒し」を足すと、癒しの作品の CV と件数が出る）。値を選ぶと、チップと検索語を保ったままその値の作品一覧へ進み、パンくずで値一覧へ戻るときも保つ。値一覧の件数と、その値を選んだあとの作品一覧の件数は、同じ集合を数えるので一致する。値一覧でもチップ列の「＋絞り込み」と検索欄を出す。値一覧がチップや検索語で0件になったときも「すべて」で探す操作を出し、同じチップと検索語のまま「すべて」へ移る。

タグやチップの行き先は、保持しているライブラリが値一覧か作品一覧かで分けない。作品詳細や、下がファイルの層から操作したときは、`mode` を `library` にして保持しているライブラリに適用する。

| 操作                                             | 行き先                               |
| ------------------------------------------------ | ------------------------------------ |
| プレビュー・作品詳細・再生中の層でタグをクリック | 「すべて」＋そのタグ                 |
| 同じ場所で Ctrl+クリック                         | 保持しているライブラリにチップを足す |
| クイックオーバーレイの追加ボタン                 | 保持しているライブラリにチップを足す |
| 「＋絞り込み」                                   | 今の一覧にチップを足す               |
| 検索欄に入力                                     | 保持しているライブラリで検索         |

遷移の純粋関数は、スマートフォルダーの定義の一覧を受け取らない。値一覧か作品一覧かで分岐しないので要らない。

検索欄の入力は、ライブラリの画面の中では履歴を置き換える（1文字ごとに積まない）。作品詳細から入力したときは、最初の入力が画面を変える遷移なので履歴を積み、戻るで元の画面へ戻れる（ファイル画面の検索欄は無効）。以降はライブラリの中の入力として置き換える。層が開いているときは、遷移の規則どおり層のエントリーを置き換える。

Ctrl+クリックで既定の動作を反転するのは、プレビュー・作品詳細・再生中の層のタグだけに残す。値一覧の値（タイル・行）とクイックオーバーレイの値は、Ctrl+クリックでも主クリックと同じくその値の作品一覧へ進む。

値を選んだあとに隣の値へ移るのは、パンくずの値から兄弟の値を選ぶ形にする。グループの値はチップではなくなったので、チップの兄弟値ドロップダウン（[ADR-0013](0013-tag-click-replaces-all.md)）はこれに置き換わる。

「＋絞り込み」の候補は、定義済みの prefix 全部・タグ・追加年にする。サイドバーのグループ分けとは連動させない。

### 再生中の層

- 入口は再生バーとポップアップの ⤢、作品詳細の「再生画面へ」。再生バーに ⤢ を新しく足す。何も再生していないときは開けない。再生バーは再生中だけ出す
- 層は URL に出さず、履歴エントリーの状態にだけ書く。開くと、URL は下の画面のまま、層を持つエントリーを1件積む。`/now-playing` はなくなる
- 閉じるボタン・Esc・ブラウザの戻るで閉じる。Esc は通常・没入のどちらでも層を閉じる。没入の切り替えはボタンだけ。閉じると履歴を1件戻り、戻った先のエントリーの URL と状態をそのまま復元する。戻り先が無いときは、置き換えで層を外す。閉じる操作は戻るが終わるまで1回だけ効き、続けて閉じても2件戻らない
- 再生していないのに層を持つエントリーに着いたとき（再読み込みや「進む」を含む）も、閉じるときと同じく1件戻る
- 層から別の画面へ進むときは、層の履歴エントリーを置き換える。下の画面がファイルでも同じ規則にする
  - 作品名 → 作品詳細（`mode: "workDetail"`）。ファイルから来ていてもファイルを抜ける。作品詳細で戻ると、層を開く前の画面（ファイルならそのファイルの位置）に着く
  - タグ → 前節の行き先の表に従う（`mode: "library"`）。選択済みのタグでも層は落として一覧へ移る
- route を書く口は「遷移」と「補正」の2つに分ける。遷移（画面へ進む操作）は必ず層を落とす。補正は事実に合わなくなった箇所だけを直し、層は変えず、履歴は常に置き換える。補正は次のものだけにする
  - 選択の解除。絞り込みで一覧が0件になったとき、または作品が存在しない（登録解除・404）ときに選択を外す
  - 作品詳細の作品が存在しない（登録解除済み・見つからない）ときは、保持しているライブラリへ置き換えで戻る。開いている層はそのまま
  - 存在しないスマートフォルダーからの退避と、今のグループ分けの形に合わない `group` の除去（`normalizeLibraryFolder`）。グループ分けが無いのに `group` がある、追加年なのに年の形でない、などを外す。形は合うが別の値として残った場合（prefix からタグへ変えたときなど）は外さず、その値の0件の一覧と「すべて」で探す操作を出す。めったに起きないので許容する
  - グループ分けを変えた保存の直後に、保持している library がそのスマートフォルダーを指していれば `group` と `groupSort` を外す。保存の応答をキャッシュへ入れる前に行い、古い `group` で作品一覧を取りにいかない。チップ・検索語・並び・seed は残す
- 補正は、上の保存直後のものを除いて、イベントで1回だけ走らせず、今の状態と事実（スマートフォルダーの定義・作品の有無）から導く。層が開いている間に補正が走ると、層のエントリーの library が書き換わるが、閉じて戻った下のエントリーには引き継がない。戻った先でも同じ補正がまた走って直る。保存直後の補正が戻った先に効かなくても、残った `group` は形の補正で外れる
- await をはさむ保存・作成・上書きは、始めたときの route（不変のオブジェクト）を覚えておき、完了したときに今の route が同じオブジェクトなら行き先へ移り、違えば何もしない。待つ間にユーザーが画面・層・絞り込み・選択を変えていれば、その状態を保つ。既定の並びの保存は行き先を持たず、応答をキャッシュへ入れるだけで今の並びも外さない（保存した並びと今の並びが同じになり、メニューの「このソートを既定にする」は消える）

### AppRoute と URL

AppRoute の `mode: "nowPlaying"` をなくし、下の画面とは独立した `layer` を持たせる。今の並び（作品・値）とランダムの seed は `library` に持つ。

```ts
type LibraryRoute = {
  folderId: string; // スマートフォルダーの ID
  group: string | null; // グループ分けで選んだ値。null なら値一覧
  selectedTags: NormalizedTag[]; // チップ
  selectedWorkId: string | null;
  q: string;
  sort: SortId | null; // 今の並び。null なら既定の並び
  groupSort: GroupSortId | null; // 今の値一覧の並び。null なら既定の並び
  seed: number; // ランダムの seed
};

type AppRoute = {
  library: LibraryRoute;
  files: FilesUrlState;
  layer: { kind: "nowPlaying" } | null;
} & ({ mode: "library" } | { mode: "files" } | { mode: "workDetail"; workId: string });
```

| 画面                 | URL                                                 |
| -------------------- | --------------------------------------------------- |
| 作品一覧             | `/library/<id>?tags=…&q=…&work=…`                   |
| グループ分けの値一覧 | `/library/by-cv?tags=…&q=…`                         |
| 値を選んだ一覧       | `/library/by-cv?group=<値>&tags=…&q=…`              |
| 作品詳細             | `/work/<id>`（変更なし）                            |
| ファイル             | `/files/<relPath>?sel=…`（変更なし）                |
| 再生中の層           | 下の画面の URL のまま（履歴エントリーの状態に書く） |

- グループの値はパスではなくクエリに置く。タグ別の値は `cv/〇〇` のようにスラッシュを含み、パスのセグメントでは扱えない
- `sort`・`groupSort`・`seed` と層は URL に載せない。履歴エントリーの状態に書く

URL とスマートフォルダーの定義の突き合わせは、純粋関数 `resolveLibraryView(route.library, folders)` 1つで行う。

- 存在しないスマートフォルダーなら `all` へ。グループ分けが無い行の `group` は無視する。形に合わない `group` は補正が外す。route 側も補正で書き戻し、URL からも外す
- 並びは選んだ行に要るときだけ解決する（今の並び → 行の既定 → 「すべて」の既定）。値一覧は作品の並びを要さない（値の並びは行自身が持ち、継承しない）
- チップと検索語は、値一覧でも作品一覧でもそのまま効かせる
- 値一覧か作品一覧か、パンくず、API に渡す条件の材料と解決済みの並びを返す

画面・クエリ・パンくず・遷移関数はこの結果だけを読む。スマートフォルダーの一覧はすべての前提になるので、起動時に先読みする。

### 履歴エントリーごとの状態

今の並び（作品・値）・ランダムの seed・層は AppRoute に持つ。sort・groupSort・seed を履歴エントリーに書くのはライブラリ画面のときだけで、ほかの画面のエントリーには層だけを書く。codec が「URL に出す部分」と「履歴エントリーの状態に書く部分」に分ける。同期は popstate と初回ロードで履歴エントリーの状態も読み戻す。同期は今までどおり項目名を参照しない汎用の仕組みにし、どれを URL に出しどれを履歴エントリーに書くかは codec が決める。同期は項目ごとのオプション（同じ URL での push、戻った件数の受け渡しなど）を持たない。push は、URL か履歴エントリーの状態のどちらかが変われば積む（層を開くと、URL は同じでも状態が変わるので積む）。`enter()` を通る入り直しは今の並びを捨てて新しい seed にする。同じ場所への入り直し（サイドバーで開いている行を押し直す、すでに「すべて」にいて「すべて」で探す）は、遷移の純粋関数が置き換えを指定する。

- 今の並び（作品・値）は、戻る・進む・作品詳細からの戻り・ファイルからの戻り・値を選んだあとの値一覧への戻りでは保たれる。端末にも DB にも URL にも書かない
- ランダムの seed は、開いている間（ページ送り、詳細から戻る、お気に入り後の再取得）は変わらない。今はアプリ全体に1つの `randomSeedAtom` を、`library.seed` に移す
- サイドバーから入り直すと、遷移の純粋関数が `sort: null`・`groupSort: null` と新しい seed を入れる。「並べ直す」も新しい seed を入れる
- seed はクライアントだけが発行する（[ADR-0040](0040-smart-folder-condition-tree.md)）。URL を直接開いて履歴エントリーの状態が無いときは、クライアントが seed を作り、置き換えで履歴エントリーに書く

## 帰結

- 縦のアイコン列と軸レールの2段がなくなり、ナビゲーションはサイドバー1本とトップバーの道具になる。履歴・お気に入り・ピン留めの無効なアイコンも消える
- 再生中を開いても下の画面が残り、閉じれば元の場所から探索を続けられる。再生バーからも1手で開ける
- [ADR-0031](0031-app-route-navigation.md) の「URL 形式は変えない」は成り立たなくなる。`/now-playing` が消え（層は URL に出ない）、`/library/<軸>` は `/library/<スマートフォルダー ID>` に、`sort=` は URL から消える。古い URL の読み替えは用意しない。nowPlaying 系の smoke は書き換える
- ADR-0031 の AppRoute から `mode: "nowPlaying"` が抜け、`layer`・`group`・`seed` が入る。`library.sort` は AppRoute に残るが URL からは抜ける。同期は URL に加えて履歴エントリーの状態も読み書きするようになる。ADR-0031 が ADR-0026 から引き継いだ「値一覧へ移るときに q・tags を消す規則」と「URL から値一覧の q・tags を復元しない規則」はなくなる。ADR-0031 が URL と無関係な状態とした `randomSeedAtom` は、`library.seed` として route に入る
- ADR-0031 が URL と無関係な状態とした値一覧の sort は、`library.groupSort` として route に入る
- 今の並びを開き直しで保てなくなる。サイドバーから入り直すと既定に戻るので、よく使う並びは「このソートを既定にする」で保存する必要がある
- [ADR-0013](0013-tag-click-replaces-all.md) の作品詳細のタグクリックは「今の軸で完全置換（値一覧なら『すべて』へ）」から「常に『すべて』＋そのタグ」に変わる。ADR-0013 の「Ctrl+クリックの反転は全入口で維持」は、プレビュー・作品詳細・再生中の層のタグだけに狭まる。クイックオーバーレイと値一覧の値は、タグの置換ではなくグループの値の選択になり、Ctrl+クリックでも反転しない。チップの兄弟値ドロップダウンは、パンくずの値から兄弟の値へ移る形に置き換わる
- [ADR-0012](0012-library-axis-as-value-browse.md) 決定7 の軸レールのホバーとクリックは、グループ分けを持つ行のクイックオーバーレイとして残る。ドラッグ中は止まる。決定7 の「どの入口でも `Ctrl`+クリックで既定動作を反転する」は、上と同じくタグの入口だけに狭まる
- [ADR-0026](0026-value-list-as-global-entry.md) の「値一覧は現在の絞り込みとは独立した全作品への入口」をやめる。値一覧でもチップと検索語が効き、値一覧の件数と値を選んだあとの作品一覧の件数は一致する。「値一覧の Ctrl+クリックはタグの反転」もなくなる。ADR-0026 は廃止になる
- 上書きを「元に戻す」で戻すと定義は上書き前になるが、表示は上書き前のチップ付きの状態には戻らない
- 値一覧の件数がチップと検索語で変わるので、値一覧から全体の分類を見るにはチップと検索語を外す
- 層は URL に出ないので、再生中の層の URL を共有・ブックマークしても層は開かない。再生の状態は再読み込みをまたがないので、開ける場面はもともと無い
- 作品詳細でもサイドバーが出るので、詳細を見ながら別のスマートフォルダーへ移れる
- サイドバーはデスクトップ専用である。[ADR-0006](0006-mobile-ui-strategy.md) の LeftNav・AddressBar を前提にした記述と、ボトムタブ「ライブラリ / スマートフォルダー / お気に入り」は、すべてがスマートフォルダーになったので、モバイルに着手するときに考え直す
- 幅の変更、アイコンだけの表示、⌘K の移動パレットは次の段階に回す
