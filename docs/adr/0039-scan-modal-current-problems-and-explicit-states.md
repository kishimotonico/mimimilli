# ADR-0039: スキャン画面の要対応は保存済みのデータから出し、「分からない」状態を空や完了と区別する

- ステータス: 承認
- 日付: 2026-11-20
- 関連: [ADR-0034](0034-scan-modal-restructure.md)（本ADRで置き換え）、[ADR-0017](0017-meta-source-projection-and-work-identity.md)（meta正本と投影）、[ADR-0028](0028-work-management-mutation-ownership.md)（必須更新）、[ADR-0029](0029-root-reconfiguration-workflow.md)（root再設定）、[ADR-0030](0030-job-progress-sse-current-state.md)（scanの完了結果の中身）、[ADR-0033](0033-dlsite-fetch-before-register.md)（未登録タブの取得と追加の一部を本ADRで置き換え）、[ADR-0036](0036-dlsite-cover-skipped-reason-and-candidate-refresh.md)（追加の警告の出し方を本ADRで置き換え）、[ADR-0037](0037-scan-session-owns-candidates-and-record.md)（記録の中身を本ADRで置き換え）、[ADR-0038](0038-dlsite-job-state-revision.md)、backlog DRAFT-70（要対応とライブラリのエラーの分担は本ADRで決める）・DRAFT-77

## 文脈

ADR-0034 で作り直したスキャン画面には、同じ根から出ている問題が3つある。

1つ目は、「分からない」が「空」や「完了」に潰れていること。候補一覧の起動時の取得は失敗を握りつぶしていて（`client/src/features/scan/ui/ScanRuntime.tsx`）、読み込み中・読み込み失敗・まだスキャンしていない・候補が0件のどれも「未登録の候補はありません」と同じ表示になる。サイドバーの完了表示は実行中から抜けたことしか見ておらず（`client/src/features/scan/ui/scanModal/useScanCompletionHint.ts`）、中止や失敗でも完了と出る。サーバーはジョブの終端を `completed`・`cancelled`・`failed` で区別して返している（`server/src/scanJobManager.ts`）が、画面がそれを使っていない。

2つ目は、要対応が「今の問題」なのに「その実行で起きたこと」として持たれていること。要対応の行は2つの出どころから組み立てている（`client/src/features/scan/model/needsAttention.ts`）。ID重複と読み取り失敗はcatalogの診断投影（`GET /api/scan/diagnostics`）から、アクセス不可・データ不整合・行方不明はサーバーのメモリにある記録（`ScanRecordStore`、`server/src/scanRecord.ts`）から読む。そのため再起動すると後者だけが消える。行方不明は「今回のスキャンで新たに」の差分だけを出すので、ライブラリのエラー（`view: "error"`、状態が `ok` でない作品）とは件数も中身も合わない。

3つ目は、未登録タブで性質の違う3つの操作が1つの選択を共有していること。取得は何も壊さず、追加は取り消せず、除外は候補を一覧から消す。それなのに初期状態で全候補を選んでいて、ツールバーの「除外」を1回押すと全候補が除外される。

骨格（モーダル、左の縦タブ、4つのタブ）はそのまま使い、この3点を組み直す。

## 決定

### 骨格とタブ

- スキャン画面はモーダルのまま、左の縦タブ（`ScanSidebar`）で「未登録 / 要対応 / 新規作品 / 更新済み」を切り替える。ページにするかどうかは別に判断する。

| タブ     | 入るもの                                                                                   | ユーザーがすること                                                                                   | 寿命                                     |
| -------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 未登録   | まだ作品になっていないフォルダー（候補）                                                   | DLsite情報を取得し、中身を見て追加する（[ADR-0033](0033-dlsite-fetch-before-register.md)）。除外する | 次のスキャンかサーバー再起動まで         |
| 要対応   | 作品とファイルの今の問題（5種類、後述）                                                    | その場で片づけるか、ファイルを直して次のスキャンを待つ                                               | 保存済みのデータから出す。再起動後も出る |
| 新規作品 | 直近のスキャンで作品になったもの（候補から追加した作品と、作品情報ファイルからの自動登録） | 基本なし。その場でタイトルを直せる                                                                   | 次のスキャンかサーバー再起動まで         |
| 更新済み | 前からある作品で、変化を自動で取り込んだもの                                               | なし。見るだけ                                                                                       | 次のスキャンかサーバー再起動まで         |

- 開いたときは、件数のあるタブを「未登録 → 要対応 → 新規作品 → 更新済み」の順に探して最初のタブを開く。どれも0件なら未登録を開く。スキャンが完了したときは、いま開いているタブが空のときだけ同じ規則で移る。
- 件数はすべてのタブに出す。0件のときと、件数が分からないとき（読み込み中・読み込み失敗）は出さない。選択中のタブでも消さない。件数の有無でタブの行の高さが変わらないよう、件数の場所は常に確保する。件数は一覧の行数とする。
- 一覧の上のツールバー行は、置くもののあるタブ（未登録・更新済み）にだけ置く。要対応と新規作品には置かない。
- スキャンの日時は、サイドバーの状態欄にだけ出す。各タブに「〜のスキャン」という見出しは置かない。
- スキャンボタンはサイドバーにだけ置く。まだスキャンしていないときは、このボタンを主ボタンの見た目にする。一覧の空表示にはボタンを置かない。
- 一覧のパスはFilesで開くリンク、作品タイトルは作品詳細を開くリンクにする。どちらもスキャンモーダルを閉じて移る。文字の操作ボタンは、アプリの中で完結する操作（別の作品として取り込む・登録解除・読み直す）にだけ置き、要対応では推奨アクションの列に置く。対象や起きていることの列には置かない。
- UIに説明文を置かない。文言・色・大きさは [design-system.md](../design-system.md) と実装に従う。

### 「分からない」を空や完了と区別する

- 4つのタブの一覧は、読み込み中・読み込み失敗（再試行できる）・まだスキャンしていない・0件を、共通の部品で区別して出す。
- 未登録・新規作品・更新済みは、サーバーを起動してからまだスキャンが完了していなければ「まだスキャンしていません」と出す。初めて使うときと再起動のあとは同じ表示にする。要対応はスキャンを待たずに出るので、この状態を持たない。
- サイドバーの状態欄は、待機・実行中・中止受付中・完了・中止・失敗の6つを区別し、見出しと内容を一致させる。日時は年入りで出す。完了を表す色は完了のときだけ使う。失敗では短い理由を出し、そこから再試行できる。
- 上のバーのスキャンの入口は1つで、件数は出さない。スキャン中と、DLsite取得ジョブにコードが残っているあいだは進捗の輪を出す（[ADR-0033](0033-dlsite-fetch-before-register.md)）。ベルは置かない。
- モーダルを閉じているあいだにスキャンが終わったら、トーストで知らせる。完了は今回の変化の件数を出し、変化がなければそう出す。中止もトーストで知らせ、失敗は自動では消えないエラートーストにする。どのトーストからもモーダルを開ける。完了で変化があったときは、入口に点を付け、モーダルを開くと消える。

### 要対応は保存済みのデータから出す

要対応は5種類とする。どれも再起動のあと、スキャンを待たずに出る。

| 種類         | 出すもの                                                                                                                                                                                                                 | 操作                                                                                                                                                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ID重複       | 同じ作品IDを持つ作品情報ファイルのパス。作品IDごとに登録済みの側を1行、未登録の側をパスごとに1行出す。各行は「登録済み」「未登録」のラベルとパスだけにする。登録済みのパスが無いときは作品名（作品詳細へのリンク）を出す | 推奨アクションの列に「別の作品として取り込む」を1つだけ置き、未登録のパスの先頭の1つを取り込む。未登録が複数なら、取り込んだあとも行が残り、もう一度押すと次のパスを取り込む（既存の `POST /works/identity-conflicts/reassign`） |
| 読み取り失敗 | 作品情報ファイルのパスと、行番号を含む原因                                                                                                                                                                               | なし。ファイルを直せば次のスキャンで消える                                                                                                                                                                                       |
| アクセス不可 | 開く権限のないフォルダーのパス                                                                                                                                                                                           | なし。権限を直せば次のスキャンで消える                                                                                                                                                                                           |
| データ不整合 | catalogの値が壊れていて一覧から外れている作品の作品ID                                                                                                                                                                    | 「読み直す」（既存の `POST /works/:id/reload`）                                                                                                                                                                                  |
| 行方不明     | 今フォルダーが見つからない作品のタイトルと最後のパス                                                                                                                                                                     | 「登録解除」（既存の `DELETE /works/:id`）                                                                                                                                                                                       |

- 行方不明は、今回のスキャンで新たに行方不明になった作品に限らず、今行方不明の作品をすべて出す。
- 行方不明とデータ不整合は、要対応とライブラリの「エラー」の両方に出す。どちらも同じデータ（作品の今の問題）を読み、件数と中身をそろえる。要対応ではその場の操作（登録解除・読み直す）を残す。
- 並びは、直すもの（ID重複・読み取り失敗・アクセス不可・データ不整合）を先、行方不明を後にする。
- 操作が成功したら対象の名前を入れたトーストを出し、行を消す。読み直しても直らないときは、そう知らせて行を残す。全部片づいたら空の表示だけにする。
- DLsite関連（RJコード未検出・取得失敗・解析失敗）は要対応に入れない。候補のものは未登録タブの行の状態で、既存作品のものは作品詳細で扱う。

### 未登録タブは取得・追加・除外を分ける

- 判断が要る行は、既定で選ばない。判断が要る行とは、DLsiteの取得結果が該当なし・失敗の行、RJコードが形式に合わない行、行方不明の作品と同じRJコードの行である。それ以外の行は、開いた時点ですべて選ぶ。取得の結果が該当なし・失敗になった行は、選択から外す。
- 判断が要る行は、ツールバーの絞り込み「問題あり」で見られる。絞り込みは押した時点の行で固定し、チェックを外しても行は消えない。
- フッターの主ボタンは1つにする。選択の中にRJコードがあって未取得の行があれば「DLsiteから取得」、なければ「追加」になる。選択の中に取得中の行があるあいだは、追加を出さない。
- 取得の進捗と中止は、主ボタンの位置に出す。取得中に未取得の行を選んで取得を押すと、実行中のジョブへ合流し（[ADR-0033](0033-dlsite-fetch-before-register.md)）、進捗の分母が増える。
- 「取得せずに追加」「項目を選んで追加」「選択を除外」は、主ボタンの詳細操作（▾）に置く。
- 追加の対象にDLsite情報のない行が含まれるときは、その件数を主ボタンの横に出し、押すとその行に絞り込む。
- 取得が失敗・該当なしだった行は、選び直して取得すれば取り直す（[ADR-0033](0033-dlsite-fetch-before-register.md) の force）。行の中の「修正」「再試行」ボタンは置かない。
- RJコードは、押すとその場で直せる。形式（`RJ_CODE_PATTERN`、RJかVJに6〜8桁）に合わないときは、入力欄の下に短い理由を出し、Escで元に戻せる。直すと未取得に戻り、選択に戻る。
- DLsite列は、未取得・取得中・取得済み・該当なし・失敗を語で出す。RJコードのない候補は「—」にする。
- 行のタイトルは、取得済みならDLsiteのタイトル、そうでなければフォルダー名を出す。省略したときは全文をhoverで出し、2行目にフォルダーのパスを添える。
- 行方不明の作品と同じRJコードの候補は、その行で知らせるだけにする。引き継ぐ操作は backlog DRAFT-77 で契約を決めてから作る。
- 除外は、ツールバーから外し、行メニューと詳細操作（▾）の「選択を除外」に置く。除外したら「元に戻す」付きのトーストを出す。ツールバーの「除外済み」から除外した候補の一覧を開き、行ごとに戻せる。設定モーダルの除外フォルダーの節は廃止する。除外のAPIは既存のものを使う。
- 追加のあと、未登録に行が残っていれば未登録に留まり、残っていなければ新規作品へ移る。追加のトーストと、カバーを適用できなかった警告には、対象の作品名を出す（複数なら「他N件」）。

### 新規作品と更新済み

- 新規作品のタイトルは、その場で直せる。新規作品からDLsite情報を取得する操作は置かない。DLsite列は連携済み・未連携を出す。
- 更新済みは、ADR-0034で決めたとおり「作品 / 変更内容」の2列とする。変化の種類は「移動」「作品情報」「ファイル構成」の3つで、ツールバーで種類ごとに絞り込める。実際に変化した作品だけを出し、エラーからの復帰や「すべての作品を読み直す」で読み直しただけの作品は入れない。値の差分は出さない。
- スキャンを始めた時点でcatalogに作品が1件もなければ、そのスキャンの新規作品は空にする。初回セットアップ、root再設定（[ADR-0029](0029-root-reconfiguration-workflow.md)）、catalogの再構築のあとも同じ規則に従う。
- スキャンの実行中に候補から追加した作品は、そのスキャンが完了したあとの新規作品にも残す。

### サーバーの契約

- 要対応の5種類は、1つの取得経路（今の `GET /api/scan/diagnostics`）で、保存済みのデータから返す。スキャンの記録には頼らない。
- アクセス不可は、ID重複・読み取り失敗と同じくcatalogの診断投影に保存する。どれもスキャンが完了したときに全置換し、中止・失敗したスキャンでは置き換えない。
- 行方不明とデータ不整合は、catalogにある作品の今の状態から導く。行方不明は状態が `missing` の作品、データ不整合は保存された値を読めず一覧から外れる作品（今は一覧の読み込みで `dataIntegrityWarning` に載る作品）である。ライブラリのエラー表示は、同じ導出を読む。
- スキャンの記録（`GET /api/scan/last`）は、完了時刻・新規作品・更新済みだけを持つ。行方不明・アクセス不可・データ不整合は記録から外す。記録の寿命と、読むときにcatalogと照合することは [ADR-0037](0037-scan-session-owns-candidates-and-record.md) のまま変えない。未スキャンのときは、完了時刻が空の記録を200で返す。
- 候補と直したRJコードは、サーバー再起動をまたいで保存しない（[ADR-0037](0037-scan-session-owns-candidates-and-record.md)）。候補一覧の応答では、サーバーの起動後にまだスキャンが完了していないことと、候補が0件であることを区別できるようにする。
- クライアントは、候補一覧の読み込み中と読み込み失敗をUIへ渡す。失敗を握りつぶさない。
- クライアントは、スキャンジョブの終端を種別（完了・中止・失敗）と失敗の理由つきで受け取り、状態欄とトーストを出し分ける。種別と理由は、ジョブのsnapshotの `status` と `error`（`GET /api/scan/:id`、SSEの `state`）で渡す。完了だけを前提にした終端の処理は置かない。
- `GET /api/scan/:id` とSSEの `state` はスキャン結果を持たず、SSEの `completed` は完了時刻だけを運ぶ。クライアントは終端を `GET /api/scan/:id` で確かめてから、記録と要対応を取り直す。新規作品と更新済みの作品本体は、`GET /api/works` の `scanRecord` 絞り込みで件数の上限なく取る。

### 決めていないこと

- 用語の統一（登録する行為を「追加」にそろえるか、「作品情報ファイル」「作品ID」と Files の「メタファイル」「Work ID」、絞り込みの「問題あり」など）は決めていない。それまでは今の語を使う。行方不明は「行方不明」のまま。
- ライブラリのエラーには、状態が `error` の作品（配置や音声に問題がある登録済みの作品）も入る。これを要対応にも出すかは決めていない。
- 起動時に自動でスキャンする設定（既定はオン）を将来入れる方向で考えている。本ADRでは決めない。

### 既存ADRのうち置き換える箇所

- [ADR-0034](0034-scan-modal-restructure.md): 全体を本ADRで置き換える。ADR-0034が [ADR-0030](0030-job-progress-sse-current-state.md) の「scanの完了結果の中身」を置き換えた内容は、本ADRの「サーバーの契約」に引き継ぐ。[ADR-0028](0028-work-management-mutation-ownership.md) の必須更新に加えたスキャンの記録（`["scan", "last"]`）もそのまま残し、要対応（`["scan", "diagnostics"]`）を、登録の集合（登録・登録解除・作品の読み直し・ID再採番・スキャン完了）に加え、meta編集・DLsiteの単体操作・同期取得・取得ジョブの終端の必須更新にも加える。
- [ADR-0033](0033-dlsite-fetch-before-register.md): 「取得中の候補は追加の対象から自動で外す」を、選択に取得中の行があるあいだは追加を出さない、に置き換える。「ツールバーの進捗枠（「取得中 n / N」）」は、主ボタンの位置の進捗に置き換える。「取得ジョブ」節のproduct codeごとの起点（まとめて／単発）と、それに基づく規則（待機中のまとめてのコードを単発で取り直すときに単発へ移すこと、進捗と輪はまとめてだけを数えること、中止は単発を止めないこと）は置き換える。取得ジョブはコードに起点を持たず、進捗はジョブのすべてのコードを数え、中止は待機中のコードをすべて外す。取り直しは、まとめての取得のリクエストの `force` で行い、取り直した行も進捗の分母と中止の対象になる。同ADRの「既存ADRのうち置き換える箇所」のうち、ADR-0030の項の「force付きの単発」と「起点がまとめてで待機中のコード」の中止、ADR-0029の項の「起点を問わず」も、これに合わせて読み替える（「起点を問わず」は「すべて」と読む）。「再試行とRJコードを直したあとの取得は、失敗の記録を無視して取り直す（force）」は、そのまま生きる。
- [ADR-0036](0036-dlsite-cover-skipped-reason-and-candidate-refresh.md): 候補の追加で「うちK件はカバーを適用できませんでした」と件数だけを出し、新規作品タブへ移りつつ警告を出す、を置き換える。警告には対象の作品名を出し、移る先は本ADRの「追加のあと」の規則に従う。クライアントが理由を出し分けない点は変えない。
- [ADR-0037](0037-scan-session-owns-candidates-and-record.md): 記録の項目から「新たな行方不明」「データ不整合」を外し、照合条件もそれに合わせて更新済みと新規作品だけにする。スキャン実行中の引き継ぎの履歴のうち、読み直しで直ったデータ不整合（`integrityResolved`）は要らなくなる。
- [ADR-0038](0038-dlsite-job-state-revision.md): 「クライアント」節の単発の保留（`pendingSingles`）は持たない。同節の作品の無効化は、単発はその場、まとめてはジョブの終わり、から、ジョブの終わりにまとめて行う、に置き換える。「revision」節の「見える状態が変わらない単発の重ね掛けでは進めない」は、見える状態が変わらない `force` の重ね掛けでは進めない、と読む。

## 採らなかった案

- 新規作品と更新済みを1つの「記録」タブにまとめる案。新規作品はタイトルを直す場所で、更新済みは見るだけの場所なので、性質が違う。
- 行方不明とデータ不整合をライブラリのエラーにだけ出し、要対応には件数とリンクの1行だけを置く案。その場で片づけられるほうが使いやすい。二重に出ることの問題は、件数と中身のずれだったので、同じデータを読むことで解く。
- 要対応を今回のスキャンの出来事としてメモリに持ち、行方不明は新たに起きたものだけを出す案（ADR-0034）。再起動で消え、ライブラリのエラーとも合わない。問題は直るまで残るものなので、保存済みのデータから出す。
- 候補と直したRJコードを再起動をまたいで保存する案。候補はフォルダーから何度でも作り直せる派生物で、保存のための専用の仕組みを持つほどの価値がない。再起動のあとはスキャンすれば戻る。
- 一覧の空表示にもスキャンボタンを置く案と、タブごとに「〜のスキャン」という見出しを置く案。同じ操作と同じ日時が何か所にも出て、画面がうるさくなる。
- 新規作品の未連携の行に「取得」を置く案。取得してから追加するという流れ（ADR-0033）が崩れ、追加後に作品が書き換わる経路が増える。取得し忘れは、未登録の主ボタンが未取得のあいだ取得になることで防ぐ。
- 「DLsiteから取得」と「追加」を常に並べ、押せないほうを無効にする2ボタン案。押せないボタンが常に並び、どちらを押すべきかがかえって読みにくい。
- 読み取り失敗とアクセス不可に「読み直す」を置く案。直すのはユーザーのファイル操作で、次のスキャンで反映される。パス単位で読み直す入口を新しく作るほどの価値がない。

## 帰結

- 要対応は再起動のあとも出て、ライブラリのエラーと件数・中身がそろう。行方不明は前から行方不明だったものも要対応に出る。
- アクセス不可を保存するため、catalogの診断投影に項目が増える。スキャンの記録は新規作品と更新済みだけになり、軽くなる。
- 読み込み中・読み込み失敗・未スキャン・中止・失敗が、それぞれ別の表示になる。
- 未登録タブで、1回の操作で全候補を除外することがなくなる。除外は元に戻せ、戻す場所もスキャン画面の中にある。
- 再起動のあと、未登録・新規作品・更新済みは次のスキャンまで「まだスキャンしていません」になる。
- docs/requirements-v4.md と docs/design-system.md の該当箇所は、実装と同時に書き換える。
