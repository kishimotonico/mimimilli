# ADR-0026: 分類値の一覧を全作品への独立した入口とする

- ステータス: 承認
- 日付: 2026-09-21
- 関連: [ADR-0012](0012-library-axis-as-value-browse.md)（決定1を本ADRで限定）、[ADR-0013](0013-tag-click-replaces-all.md)、[ADR-0016](0016-view-axis-consolidation.md)、[設計レビューの引き継ぎTODO](../review-todo-2026-09-20.md)、backlog TASK-457

## 文脈

ADR-0012 は軸を「値をブラウズするためのビュー」と定め、軸を切り替えても絞り込みは維持されるとした。一方で、値一覧が現在の絞り込みの中の分類を示すのか、ライブラリ全体の分類を示すのかは決めていない。

設計レビュー（2026-09-20、C4）は、通常一覧・スマートフォルダー・facet で条件の集合が揃っていないことを指摘した。具体的には、表示されている検索語をスマートフォルダーの query が受け取らない経路があり、facet の件数が主クリック後の集合と一致しない。件数が何を数えたものなのかが画面から読み取れないため、値を選ぶ前と後で結果が変わる。

## 決定

分類値の一覧は、現在の絞り込みとは独立した、全作品への入口とする。

件数はライブラリ全体の件数を表す。その値を持つ作品の総数であり、現在の絞り込みを適用した後の件数ではない。件数の意味を画面上で読み取れるようにする。

値一覧を表示している間、適用されない絞り込み条件を、適用されているかのように見せる状態を作らない。値一覧に効かない検索語やフィルタを入力欄・チップ列に残したまま提示しない。

facet の件数と、値を選んだ後に表示される作品一覧の件数は一致しない。これは不整合ではなく、両者が別の集合を数えているという仕様である。

ADR-0013 のクリック意味（通常クリックは完全置換、AND 追加は可視ボタン）は変更しない。`year` 軸の単一選択、作品検索と値名検索の分離も維持する。任意の検索式を扱う汎用の AST は導入しない。保存ルールの OR・除外を捨てる場合は、失う表現力を実装タスクで明記する。

### ADR-0012 からの限定

決定1 の「軸を切り替えても絞り込みは維持される」は、作品一覧の間での軸切り替えに限定する。値一覧は絞り込みの外にある入口として扱う。

### 実装タスクで決めること

値一覧から作品一覧へ戻るとき、値の選択が既存の絞り込みを引き継ぐのか置き換えるのかは、この ADR では決めない。ADR-0013 の置換規則と URL 復元時の意味が一致することを条件に、実装タスクで決定する。

## 帰結

- 値一覧の件数計算が現在の絞り込みから切り離される。絞り込み条件を facet の集計へ渡す経路が不要になる。
- 「お気に入り＋検索語の状態でタグ候補の件数を見て追加する」という絞り込み方はできなくなる。値一覧の件数は全体を指すため、絞り込みを重ねた結果の件数は作品一覧で確認する。
- 値一覧と作品一覧が別の集合を扱うため、両者の件数表示には異なるラベルが要る。同じ見た目で並べない。
- URL から復元した状態でも、入力欄・一覧・件数が同じ条件を表すことを受入条件に含める。
- 既存の core/SQL の分離と同値性確認は維持する。性能の推測だけを理由に全 SQL 化しない。
