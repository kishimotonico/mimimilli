# ADR-0020: smokeのwebServer readinessをログ待ちにする

- ステータス: 承認
- 日付: 2026-08-15
- 関連: ADR-0018（Vite/Bun分離）、TASK-217、TASK-307、TASK-336

## 文脈

TASK-307は当初「Vite依存最適化のフレーク」と誤診されていたが、実態は環境障害だった。このWSL2（mirrored networking）には、127.0.0.1の未使用ポートへのTCP接続がRSTなしで約2分ハングする既知の障害がある（microsoft/WSL #41102, #40169）。正常にimmediateでrefusedされるのは、その時点の `/proc/sys/net/ipv4/ip_local_port_range`（幅4096）の範囲内のポートに限られ、この範囲はWSL再起動のたびに移動する。2026-08-15の調査で機構を確定した: 現象はゲスト内部限定・IPv4限定で、Windows起点の接続では再現しない（ゲストのFSE steering起因）。`wsl --shutdown` でも直らない。

PlaywrightのwebServerは `url`/`port` を指定すると、サーバー起動前から生TCP接続によるプローブを打ち続ける。このプローブがエフェメラル範囲外のポートに当たるとハングし、本来35秒で終わるsmokeが2.9〜5.2分かかっていた。Playwright 1.60のソースを確認したところ、`url`/`port` を指定せず `wait: { stdout | stderr: RegExp }` のみを指定した場合、起動前TCPプローブのコードパス自体に入らないことが判明した。

## 決定

smokeのwebServer readinessを、HTTPプローブ（`url`）からログ行待ち（`wait.stdout` / `wait.stderr`）に変更する。

| 代替案                       | 却下理由                                                                                                    |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------- |
| ポート帯の移設               | エフェメラル範囲が再起動ごとに移動するため恒久対策にならない                                                |
| NATモードへの切替            | この環境はSSH運用のため不採用                                                                               |
| `wsl --shutdown`             | 実測で直らないことを確認済み                                                                                |
| リポジトリ内の環境検知ガード | 環境固有の分岐をリポジトリに持ち込まない方針で過去にrevert済み。`wait` はPlaywright標準機能であり該当しない |
| portless経由での起動確認     | smokeのportless非依存（ADR-0018）を壊す                                                                     |

## 帰結

- readinessの根拠が「HTTP応答の確認」から「起動完了ログ行の出現」へ弱まる。ログ行が出た直後にポートがまだ受け付け不可という理論上の窓は残るが、実運用上の待ち時間は解消される
- `reuseExistingServer` はwaitモードのコードパス上参照されないため、両webServerエントリから削除した
- ポート衝突時の失敗を明示化するため、Vite側は既存の `--strictPort` を維持し、Bun側はbind失敗時に例外で即終了することを実測で確認した
