## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-451（Done）は現行フローの調査と、2026-09-22に採用した導線方針の記録であり、仕様全体の決定や実装完了を意味しない。このドラフトは、TASK-451で「別途決める」とした利用者向けの詳細を一つにまとめる。

2026-09-22に採用済みの前提は次のとおり。
- 通常の物理スキャンからDLsite取得を暗黙にenqueueしない。登録時にコードのある作品をまとめて取得する明示選択を置く。
- 取得情報は差分を確認してから明示的に適用し、一括承認を用意する。未設定項目だけの自動補完と、過去のDLsite適用値への自動追随は採用しない。
- 復帰先はDLsite専用管理ビューとし、作品詳細からの単体取得・差分確認・適用は残す。

既存の追跡先との分担:
- DRAFT-47は作品編集ダイアログの保存モデル、RJ/VJコード確定と取得操作、編集中draftとの境界を扱う。このドラフトでは編集画面の保存方式を再定義しない。
- DRAFT-63は一括取得の結果を見返す契約とrefresh運用を扱う。直近結果をどの画面で見せるかはこのドラフトで決め、結果API・再試行・refreshの実装要件はDRAFT-63へ渡す。
- TASK-460は最終取得失敗の表示、cache TTL、結果表示の寿命を分ける方針と、user DB単独復元時の案内を扱う。このドラフトでは直近ジョブ結果の保持上限を決め、TASK-460の失敗表示の寿命と混同しない。
- TASK-461はDRAFT-63/DRAFT-66の現行コードとの前提ずれを直す。このドラフトの決定をDRAFT-63へ反映する際の前提整理を担当する。

本ドラフトで決めること:
1. 登録時取得選択の初期値と前回選択の記憶範囲。DLsite連携を選ばない作品を取得対象にしないこと、明示選択が登録完了後にどの単位で予約されるかを確定する。
2. 専用DLsite管理ビューの常設入口、登録完了・通知・作品詳細からの遷移、画面内の進行中・確認待ち・失敗・直近結果の配置とレイアウトを確定する。
3. 適用方式は「差分確認後の明示適用＋一括承認」で確定済みと記録する。未設定項目の自動補完と過去値の自動追随は不採用として、実装で別方式へ戻らない条件を明文化する。
4. サーバー再起動後の実行途中ジョブ、確認待ち候補、直近結果の扱いを決める。自動再開、中断・要確認、手動再実行のどれを採るか、適用操作を自動再送しない条件を含める。
5. 直近取得結果の保持上限と削除契機を決める。確認待ち・現在の取得状態・最終取得失敗・直近ジョブ結果・取得履歴を別の寿命として定義し、無期限の履歴や自動undoを前提にしない。
6. 一括承認の選択粒度と対象集合を決める。作品単位・項目単位の選択、全選択・一部選択、取得直後の対象固定、差分の競合時の再確認が十分かを確定する。

通常スキャンからの暗黙取得を戻すこと、未設定項目の自動補完を採用すること、外部情報へ自動追随すること、作品詳細の単体操作を削除することは本ドラフトの対象外であり、採用しない。
