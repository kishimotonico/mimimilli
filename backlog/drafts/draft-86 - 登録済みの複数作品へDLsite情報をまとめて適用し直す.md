## Description

## 動機
2026-11 にDLsiteの作品ページ構造が変わり、パーサーがタイトルしか取れないまま約80作品がタグ空・カバーなしで登録された（TASK-524 でパーサーは修正）。登録済み作品を直す経路は作品詳細の「取得結果を確認」→「選択内容を適用」を1件ずつ行うことしかなく、ページ構造の変化は今後も起きうる。

## 経緯と守ること
旧「まとめて適用」（未設定項目を適用）は TASK-511.8 / ADR-0033 で廃止した。理由は、全作品の差分を1リクエストで同期計算してエラーになった、適用中にカバーをHTTP取得していた、差分計算がclientとsharedの2系統だった、クライアントが送る取得結果を信用していた、対象を指定しない暗黙の全件取得、表示の重複（ADR-0034）。ADR-0033 は「ライブラリで複数作品を選び右クリックから選択的に再スキャン・取得する機能を作るまで、既存作品をまとめて反映する入口は置かない」としている。
- 対象はユーザーが明示的に選んだ作品だけ
- 差分計算は shared の computeDlsiteWorkDiff / defaultDlsiteApplySelection / planDlsiteApply を作品詳細と共有する
- 全件の差分を1リクエストで同期計算しない
- 取得結果はクライアントから受け取らず、サーバーがキャッシュから読む。適用中はHTTPを出さない

## イメージ（未確定）
1. ライブラリで作品を複数選び、右クリック（または選択中の操作）から「DLsite情報を更新」
2. 選んだ作品のRJコードを既存の取得ジョブ（POST /dlsite/jobs）で取得。キャッシュがあれば通信しない。カバーも先取りする
3. 確認ダイアログ: 作品ごとに1行で変化の要約（例: タグ +8・カバー・URL）。変化なし・取得失敗は分けて出す。行ごとに除外できる
4. サーバーがキャッシュから1作品ずつ適用し、結果を件数で出す（更新◯件、カバーを入れられなかった△件）
既定の選択は作品詳細と同じ（未設定のタグ・カバー・URLを足す。既存のサークル・年齢指定タグの置き換えとタイトル変更はしない）。上書きしたい作品は作品詳細から個別に行う。

## 前提と依存
- ライブラリに複数選択も作品の右クリックメニューも無い（selectedWorkId は単一）。DRAFT-53（作品の一括選択・一括操作）が前提になる
- 対象を集めるためのスマートフォルダー条件（DLsiteタグ無し・カバー無し・RJコードあり等）は無い。DRAFT-37（条件フィールド拡充）と関係する
- 再利用できる部品: 取得ジョブと進捗ストア（entities/dlsite/model/dlsiteJobStore.ts、useDlsiteFetchFrame）、DlsiteApplyDialog・DlsiteDiffRow（props駆動）、POST /dlsite/:id/apply

## 未決事項
- 入口: ライブラリの複数選択＋右クリックを待つか、それより前に別の入口（スマートフォルダーやエラー絞り込みの一覧からの操作など）を置くか。ADR-0033 の起点の規則に新しい起点を足すADRが要る
- 確認ダイアログで作品ごとに項目（タグ・カバー・URL）まで選べるようにするか
- 差分の計算をどこで行うか（作品ごとのリクエストを分割して送る／ジョブの終端で計算する）
- 適用を同期の分割リクエストにするかジョブにするか、中止・途中失敗の扱い
- 適用対象の作品が確認後に変わったときの扱い（sourceRevision による弾き方）
