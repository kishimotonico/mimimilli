## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
2026-08-03のマージレビュー時にユーザーから出た要望（同日、RJコードのフローについて追記）。

現状の作品編集まわりは、フィールドやセクションごとに保存ボタンが分かれている（例: DlsiteEditorの「コードを保存」、WorkEditDialog・タイトル編集など経路ごとの保存）。これを全体的に見直したい。

方向性の候補（未決）:
1. 編集画面全体で「まとめて保存」1ボタンに集約する
2. 保存ボタンを無くしリアルタイム反映（自動保存）にする

## RJ/VJコードのフロー（ユーザー合意済みの方向）

- コード変更はTASK-144の連携リセット＋再取得という重い副作用を伴うため、リアルタイム自動保存の対象にはしない
- 明示アクションは「作品情報を取得」のようなボタン1つでよい。コードの確定（保存）はこのボタンに統合し、独立した「コードを保存」ボタンは廃止する方向
- 検討点: 取得失敗時・オフライン時（MIMIMILLI_DLSITE_OFFLINE）にコードだけ確定させたいケースがあるか。無いなら完全統合、あるなら失敗時のフォールバック挙動を決める

## 着手前に決めること

- 全体の保存モデル（まとめて保存 / リアルタイム / フィールド種別ごとのハイブリッド）。軽いフィールド（タイトル・タグ等）はリアルタイム、副作用が重いコード系だけ明示アクション、というハイブリッドが有力候補
- リアルタイム反映の場合: デバウンス、失敗時のリトライとエラー表示、楽観更新の巻き戻し
- まとめて保存の場合: 未保存変更の管理、閉じ操作との関係（TASK-119のprogressive dismissal「編集中は編集のみキャンセル」との整合）、バリデーションのタイミング
- 対象範囲の棚卸し: WorkDetail内のインライン編集・WorkEditDialog・DlsiteEditor・ScanModalのタイトル編集・SettingsModalのフォルダーパス等、どこまで統一するか

着手を決めたらまず「保存モデルの要件を決める」タスクを切る。
