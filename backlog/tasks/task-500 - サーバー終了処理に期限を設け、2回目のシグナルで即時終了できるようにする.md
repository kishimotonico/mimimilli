## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
performGracefulShutdown は server.stop()→app.shutdown()（root再設定・scan・DLsiteの取消と待機）→adapter.close() の順で、どこにも期限が無い。スキャンの取消はAtomicsトークンによる協調キャンセルなので、ワーカーが長い同期I/O（ネットワークドライブ等）で止まると戻らない。index.ts の shuttingDown ガードで2回目のSIGINT/SIGTERMは無視されるため、SIGKILL以外に抜ける手段が無い。全体に期限を設け、超えたらワーカーをterminateして終了する。2回目のシグナルでは待たずに終了する。受理済みHTTP要求の待機や段階的な終了処理までは作り込まない。Windowsネイティブ（Ctrl+C）でも同じに動くこと。詳細は doc-6 の jobs-4。行番号は点検時点（1c9f033c）のもの。先に入るバグ修正で変わり得るので、着手時に現状を確認してから進める。
<!-- SECTION:DESCRIPTION:END -->
