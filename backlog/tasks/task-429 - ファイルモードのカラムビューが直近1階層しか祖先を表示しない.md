## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
ファイルモードのカラムビューは直近1階層しか祖先を表示せず、深い物理パスで現在地と戻り先を把握できない。物理FSファイラーという位置づけを維持し、祖先を省略可能なパンくずとして表示する。

前提（統合済みの変更）: TASK-428.18 が Files 系を大きく改修済み。404と5xx/通信失敗の区別（ApiRequestError.status===404 で判定、404では合成entryを組み立てない）、単一ファイル作品の登録済みバッジと実タイトル表示（単一ファイル作品のときだけ GET /works/:id を追加取得）、再生ボタンの状態別トグル、プレビューの閉じる・ドラッグリサイズ（filesPreviewWidthAtom、localStorage永続化、320〜720pxクランプ）・狭幅時の全幅切替（container query、720px以下）、絶対パスコピー（joinPath(rootFolder, entry.path.split("/")) で実OS絶対パスを合成、ローカル専用の明示は常時表示のヒント文）、選択対象が一覧から消えているケースの対象なし表示（isFilesSelectionMissing、FilePreviewMissingSelection）。

レイアウトの主従が反転している点に注意。一覧カラム（.mle-filestage）は300px固定から flex:1 になり残り幅を取る主役、プレビューが確定幅を持つ側になっている。

TASK-428.5 が client/src/entities/file-system/model/navigationAtoms.ts に openPathInFilesAtom を新設し、その後 physicalPath（絶対パス）を root 相対へ正規化する修正が入っている（relativeToRoot を使い、引数は { path, root }）。ライブラリのエラー詳細とスキャンの要対応タブから Files を開く導線がこれを共有している。

TASK-428.18 の担当（エージェント名 t428-18）が worktree を残して質問に対応できる。

対象の確定（2026-09-07、オーナー決定）: DRAFT-42 および監査所見 files-A-18 の対象は、アドレスバーのパンくずではなくファイルモードの折り畳み帯（StackEdge.tsx / ColstackBackButton）である。パンくずは既に全階層を表示できており実害は小さい、というのが監査の判断。当初この取り違えのまま着手し、アドレスバーのパンくずへ中間省略を実装した経緯がある。

方式は (b) 縦書き背表紙の意匠を維持し、祖先ごとに背表紙を1枚ずつ積む。横書き帯の新設はアドレスバーのパンくずと同じ情報が2つ並ぶため不採用（DRAFT-41 の懸念を増やさない）。

仕様:
- root から現在地の親までを左から順に背表紙として並べる
- 各背表紙は独立したボタン。aria-label に階層名、Enter/Space で移動、矢印キーで隣の背表紙へ
- 表示上限は3枚程度。超える分は中間を「…」1枚に畳み、クリックで畳まれた祖先の一覧メニューを開く
- 既存の4枚の縁の演出は「束の先頭（root側）」だけに残す。深さ変化のパルスは現在地に最も近い1枚だけに掛ける
- 出入りのアニメーションは ADR-0014 どおり、AnimatePresence の条件レンダー境界を背表紙1枚ごとに持たせる。variant は useMotionVariants のビルダー経由で組み、delay の直書きは禁止
- 縦書きの長い名前は 46px 幅の高さ方向で ellipsis

コミット済みのアドレスバー側の中間省略（Breadcrumbs.tsx の測定用クローンによる折り畳み、ResizeObserver、テスト付き）は本タスクに含めたままでよい。同じ「祖先への到達性」の改善で副作用がなくレビュー通過済みのため。ただし背表紙側の拡張が入るまで本タスクを完了扱いにしないこと。
