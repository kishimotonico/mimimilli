## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
設計レビュー2026-08-14。現状の候補一覧は1件がタイトル・パス・音声件数の3行を占め、パスがbreak-allで折り返して行高が不揃い。また「選択したものを除外」がチェックボックス選択を使うため、同じ選択が「追加したい」と「永久に無視する」という正反対の意味を持ち違和感がある。さらに除外はuser DBへ永続化されるのに解除UIがなく、実質不可逆な操作が確認なしで実行できる（UXルールのConfirmation Dialogs違反）。UI仕様: 1件1行のテーブル（列はチェックボックス・フォルダー名・RJコード・フォルダー・音声・✕）／パスは折り返さず末尾省略／ヘッダーにマスターチェックボックス（一部選択時は横棒表示）／RJコード列は検出値をそのまま表示、未検出は「未検出」と薄く表示し、クリックで入力欄になり手入力できる（空のまま登録可）／行の✕で1件ずつ候補から外し、「元に戻す」付きトーストを出す（取り消せるため確認ダイアログは不要）／まとめて候補から外す機能は作らない／操作バーは選択件数と「N件をライブラリに追加」のみ（「すべて登録」はマスターチェックボックスと重複するため廃止）／説明文は「まだライブラリで管理していないフォルダーです。追加するとmimimilli.jsonを作成して、作品として管理します。」。追加後はタブを自動遷移させず、追加した行が消えてトースト（「N件をライブラリに追加しました」＋「新規登録済みを見る」）を出す。ただし未登録が0件になったときだけ新規登録済みへ自動で切り替える。
