## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
マージ前の最終検証（2026-08-05）で見つかった、ライブラリ再設計が作り込んだ不具合。

## 症状

タグで絞り込んだ状態で作品を選択しプレビューを開くと、結果面上部のチップ列の右側がプレビューパネルに物理的に覆われ、「すべてクリア」ボタンが押せなくなる。

実測では「すべてクリア」ボタンの矩形（x:1204-1272）がプレビューパネルヘッダー .mle-prv__hd の矩形（x:861-1280）に完全に含まれており、クリックすると「別要素に覆われている」エラーになる。Escape でプレビューを閉じれば押せるため機能自体は失われていないが、操作導線としては到達不能になっている。

## なぜ直すか

チップ列（TASK-180）もオーバーレイでスライドインするプレビュー（TASK-180）も、どちらも今回の再設計で導入したもので、この組み合わせは再設計前には存在しなかった。既存の問題ではない。

さらに ADR-0012 §2 はチップ列を「選択されたフィルタの唯一の表現」と位置づけている。その唯一の表現が覆われて操作できない状態は、仕様の意図と噛み合わない。フィルタの解除は作品を見ながら行いたい操作でもある。

## 対応方針（統括判断）

チップ列はプレビューに覆われないようにする。プレビューのスライドイン領域をチップ列より下に限定するか、チップ列を前面に置くかは実装者判断でよい。ただし以下を満たすこと。

- プレビュー表示中でもチップの追加・個別解除・すべてクリアがすべて操作できる
- チップ列とプレビューが視覚的に重なって読みにくくならない（半透明で重ねて逃げる形にはしない）
- z-index を新設する場合は docs/design-system.md の z-index 規約に従い、表に追記する

なお「すべてクリア」だけでなく、チップ数が増えて右端まで伸びたときに個別の × も同様に覆われるはずなので、ボタン1つの位置調整では解決しないこと。

対象: client/src/features/library/ui/FilterChipBand.tsx / PreviewPane.tsx / LibraryView.tsx / client/src/styles/shell.css
