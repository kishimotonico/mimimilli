## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
ライブラリビューで分類軸を切り替えると、フェッチ中に件数表示が「0 件」に落ちて空画面に見えるちらつきが起きる。原因は total 未確定（undefined）と実際の0件を区別しない状態モデル（total ?? works.length パターン）。件数を「未確定 | 確定(number)」として扱い、未確定時は件数を描画しない。

対象箇所:
- client/src/features/library/ui/preview/AxisLanding.tsx:25 の total ?? works.length
- client/src/features/library/ui/preview/SmartFolderView.tsx:107 の件数表示
- client/src/features/library/ui/WorkGrid.tsx:383 と DrillHeader count（:374）
- client/src/features/library/ui/ContentColumn.tsx:350 のヘッダー、:117・:243 の facetItems 件数

あわせて件数の意味（サーバー総件数か、ロード済み件数か）を全箇所で統一する。AxisLanding / SmartFolderView にはローディング状態を props で渡す。
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 分類軸・ビュー切り替え直後のフェッチ中に、画面のどこにも「0 件」が表示されない（未確定時は件数そのものを描画しない）
- [x] #2 データが実際に0件のときは従来どおり0件・空状態が表示される
- [x] #3 件数表示の意味（総件数/ロード済み件数）が全箇所で統一され、ユニットテストで未確定と0件の描画差が検証されている
- [x] #4 pnpm check と pnpm test が通る
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Cursor (composer-2.5) が実装。total != null のときだけ件数を描画する方針に統一（AxisColumn/DrillHeaderと同じ規約）。worksTotal はクエリ pending 中 undefined になるため isLoading prop は不要と判断。works.length フォールバックは全廃、SmartFolderView の works prop と PreviewPane の smartFolderWorks 配線も未使用化に伴い削除。pnpm check / pnpm test（client 623 + server 445）通過を統括側でも再確認済み。ブラウザ実機確認はブランチ全体の最終検証でまとめて実施予定。
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
件数表示を「未確定(undefined)は非描画・確定(0含む)は表示」に統一し、フェッチ中の「0 件」誤表示を解消。AxisLanding/SmartFolderView/WorkGrid/ContentColumn を worksTotal ベースへ寄せ、ユニットテストで未確定と0件の描画差を検証。pnpm check / pnpm test 通過。
<!-- SECTION:FINAL_SUMMARY:END -->
