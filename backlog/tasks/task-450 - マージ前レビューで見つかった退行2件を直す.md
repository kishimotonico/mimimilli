## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
feat/ui-ux-intake を master へマージする前に、同ブランチ上で対応する。

退行1: スキャン再試行後に古いエラートーストが残る
- 該当: client/src/features/scan/ui/ScanRuntime.tsx:94-96 付近
- 症状: スキャン失敗でerror variantのトーストを表示した後、再試行して成功しても古いエラートーストが消えない。
- 原因: scanJob.error が null に戻る分岐で早期リターンしており toast.dismiss() を呼んでいない。error variantは自動消滅しない契約（docs/design-system.md）。トースト要求は発行元ごとに1件で上書きされるが、handleScanTerminal の完了トーストは if (!scanModalOpen) の中にしかないため、スキャンモーダルを開いたまま再試行すると上書きも起きず残り続ける。
- 期待: エラーが解消された時点で、その発行元のトーストを明示的に破棄する。

退行2: 矢印キーで選択した子フォルダーのプレビューが親フォルダーの内容を扱う
- 該当: client/src/features/files/model/useFilesBrowse.ts:85-86
- 症状: Filesの一覧で矢印キー移動して子フォルダーを選択すると、previewEntry はその子になるが folderEntries には親フォルダーの entries が入ったままになる。結果、プレビューの種類別件数が兄弟項目を数え、親に音声ファイルがあると子フォルダーの「先頭の音声を再生」で親の音声が再生される。playbackSourceEntries（folderEntries ?? entries）も同じ経路。
- 背景: 矢印キーでのフォーカス移動（client/src/features/files/ui/FileColumn.tsx:57 の onFocusItem）はクリックと異なりフォルダーに潜らず選択だけするため、この食い違いが生じる。この移動機能自体が feat/ui-ux-intake で追加されたものなので、同ブランチが作り込んだ退行。
- 期待: 選択中ディレクトリの内容を別途取得するか、未取得の間は親の一覧を子の内容として扱わない。
