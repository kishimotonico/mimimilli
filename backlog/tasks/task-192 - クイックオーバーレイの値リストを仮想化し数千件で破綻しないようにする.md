## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
実機での使用感の指摘（2026-08-05）で判明した実装漏れ。ライブラリ再設計のブランチ内で対応し、マージ前に解消する。

値一覧本体（AxisValueRows / AxisValueGrid）は @tanstack/react-virtual で仮想化されているが、**クイックオーバーレイ内のリスト（AxisValueQuickList）は仮想化されていない**。全件を DOM に展開している。

これは新機能ではなく設計意図に対する未達である。ADR-0012 §7 は「CV・サークルは数百規模になりうるため、素早い乗り換えとじっくり探す操作を分離する」ことを理由にホバー／クリックの2導線を設けており、そのうち素早い乗り換え側の受け皿がクイックオーバーレイである。ここが件数に耐えないと分離の前提が崩れる。

実利用では CV・サークルの値が数百〜数千件になることが想定される。

## やること
- AxisValueQuickList を仮想化する。値一覧本体と同じ @tanstack/react-virtual を使い、実装を二重に持たない
- オーバーレイの高さは画面内に収まる上限を持ち、超える分はパネル内スクロールにする
- キーボードの上下移動で仮想化範囲外の項目へ移動したとき、スクロールが追従してフォーカスが見えること
- ホバーで開いてから描画が完了するまでの体感（オーバーレイは200msホバーで開くため、開いた瞬間に重いと操作が破綻する）を実測すること

## 計測
値が2000件規模の軸で、オーバーレイを開いてから操作可能になるまでと、検索文字入力時の応答を実測し、仮想化前後の差をタスクの実装ノートに記録すること。フィクスチャに大量データが無い場合は計測用のデータを一時的に用意してよい（リポジトリには残さないこと）。

対象: client/src/features/library/ui/AxisValueQuickList.tsx / AxisQuickOverlay.tsx / AxisValuePopoverPanel.tsx（チップの兄弟値ドロップダウンも同じ問題を抱えていないか確認すること）

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
計測（2026-08-05、Chromium/agent-browser、CV軸に一時的な2000件フィクスチャをfetch差し替えで注入。リポジトリには残していない）:
- 仮想化前後のDOM生成コスト比較（同一ブラウザでの直接DOM操作ベンチ、レイアウト強制込み）: 2000ノード ≈ 84.2ms、20ノード（仮想化後の実描画数相当） ≈ 2.9ms。約29倍の差。Reactの差分適用コストは含まないため、実際の非仮想化コストはこれより更に大きい
- 実機（React経由）: ホバーからオーバーレイ操作可能までの体感 ≈ 350ms（うち200msは意図的なホバー遅延、残りが実描画コスト）。2000件でもDOM描画行数は17〜25件に収まっている（仮想化確認）
- 検索文字入力（1文字絞り込みで2000件→1件）の応答: fillコマンドで18ms、遅延なし
- チップの兄弟値ドロップダウン（AxisValuePopoverPanel）も同じAxisValueQuickListを使うため同様に仮想化されていることを確認（2000件で17行のみ描画）
- 実装中に発見・修正: キーボード上下移動でのフォーカス追跡をdocument.activeElementからの逆算にしていたところ、フォーカス確定（ダブルrAF）より速い連続キー入力で位置を見失うレースコンディションがあった。activeIndexRefで自前追跡する方式に変更し解消（通常速度・OS標準キーリピート相当の間隔では取りこぼしなし）
