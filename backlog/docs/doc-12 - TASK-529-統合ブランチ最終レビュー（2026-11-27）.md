### should

### 1. UnregisteredFooter が capture 段のハンドラ3本で Ark のメニュートリガーを横取りしている

- 場所: `features/scan/ui/scanModal/unregistered/UnregisteredFooter.tsx:57, 116-142`
- 問題: ▾ を「メニューのトリガー」かつ「項目選択ポップオーバーの `ids.trigger`」にしたため、ポップオーバーを開いたまま ▾ を押すと、ポップオーバーは閉じず（トリガーは dismissable の exclude）メニューが開く。これを止めるために、外枠の div に `onPointerDownCapture`・`onClickCapture`・`onKeyDownCapture` と `closedOnTriggerPress` の ref を置き、Ark のトリガーへイベントが届く前に握りつぶしている
- なぜ問題か:
  - doc-11 §4 は「トリガー再押下は #1・2・7 も ids のトリガーが同じ扱い」としているが、`ids.trigger` は id を差し替えるだけで `getTriggerProps()` の onClick（TOGGLE）は付かない（`popover.connect.mjs` の `getTriggerProps`）。設計の前提が外れた分を、機能側のコンポーネントが zag のイベント順の知識（pointerdown で preventDefault、click で `TRIGGER_CLICK`）で埋めている
  - 止めているキーは Enter と Space だけ。zag のメニュートリガーは ArrowDown・ArrowUp でも開く（`menu.connect.mjs` の `onKeyDown`）。ポップオーバーを開いて Shift+Tab で ▾ へ戻り ArrowDown を押すと、メニューが開き、フォーカスが外へ出たポップオーバーが閉じる。Enter は「閉じるだけ」、ArrowDown は「メニューに切り替わる」で、キーによって結果が違う
  - Ark を上げてトリガーの開き方が変わると、この3本は黙って効かなくなる
- 直し方の方向: 横取りをやめて、メニューの開く要求を Ark の口で受ける。`SplitButton` がメニューの `open`／`onOpenChange` を受け取れるようにし（`UseMenuProps` はそのまま通る）、Footer 側で `onOpenChange({ open: true })` のとき `pickerOpen` なら開かずに `setPickerOpen(false)` する。ポインターも全キーも同じ経路になる。ADR-0043 に「open を制御して close を捨てる方式」で不具合が出た記録があるので、制御にした場合のキーボードオープン時のハイライトは確かめること。もう一つの案は、#7 だけ `ids.trigger` をやめること（▾ を押すと外側クリックでポップオーバーが閉じ、メニューが開く。戻し先は `resolveFocusReturnTarget` が ▾ を引けるので変わらない）。どちらにするかは仕様の判断だが、今の形は残さない方がよい

### 2. パンくずのトリガー id を DOM へ直接書き、切れたときの補修を別経路で持っている

- 場所: `features/library/ui/LibraryBreadcrumbs.tsx:34-35, 61-69`、`features/library/ui/GroupValuePopover.tsx:32, 106-111`
- 問題: クリックのハンドラで `anchor.id = triggerId` と、`shared/ui/Breadcrumbs` が描いた要素へ id を命令的に付けている。React は付けた id を知らないので、ボタンが作り直されると id が消える。その補修として `onReturnTargetLost` があり、`crumbsRef.current.querySelector("button.mle-crumbs__seg.is-last")` で共有部品の CSS クラス名を頼りに探し直して id を付け、フォーカスしている
- なぜ問題か:
  - `onReturnTargetLost` は `list.onSelectValue(value)` の直後に同期で `returnTarget.isConnected` を見る。遷移は flushSync していないので、この時点ではまだ再描画されておらず、「値を選んだ結果アンカーが作り直された」ケースは拾えない。発火するのは、開いている間に id がすでに切れていたときだけ
  - その状況は今のライブラリのパンくず（最大3セグメント。`Breadcrumbs` は 4 以上でしか省略しない）では起きない。つまり実質到達しないコードで、テストも無い（`tests/` に `onReturnTargetLost` の参照なし）
  - `GroupValuePopover` と共通フックの公開面が、この1か所のために広がっている（`onReturnTargetLost`、`handle.resolveReturnTarget`）
- 直し方の方向: `Breadcrumbs` に最後のセグメントの id（または `getSegmentProps(index)`）を渡せるようにして、JSX で宣言的に付ける。作り直されても id が残り、`resolveReturnTarget` の 3（`getTrigger()` を id で引く）がそのまま効く。`crumbsRef`、`onReturnTargetLost`、クラス名での探索は消せる。`siblingAnchor`（要素）も開閉の boolean で足りる（3 を参照）

### 3. `anchorEl` と `getAnchorRect` は、`ids.trigger` と同じ要素を二重に渡している

- 場所: `features/library/ui/GroupValuePopover.tsx:26, 83`、`features/library/ui/LibrarySidebarPanel.tsx:172`、`features/library/ui/LibraryBreadcrumbs.tsx:45`
- 問題: zag の位置合わせは `anchorEl ?? getActiveTriggerEl()` を基準にする（`popover.machine.mjs` の `trackPositioning`）。`getAnchorRect` が null を返すと基準要素の矩形へフォールバックする（`popper/get-anchor.mjs`）。サイドバーの行もパンくずの値も、`triggerId` を持つ要素と `anchorEl` は同じ要素なので、`getAnchorRect` は無くても同じ位置に出る
- なぜ問題か: 同じ要素を id と要素参照の2経路で渡しているので、片方だけ古くなりうる。サイドバーは退出中 `anchorEl` が null、id は生きている。パンくずは 2 のとおり id が切れると要素参照は切り離された古い要素を指す。`GroupValuePopover` の props が 10 個あり、うち `anchorEl`・`onReturnTargetLost` は不要、`panelHandlers`・`onPanelElChange` は coordinator 専用で、汎用部品の顔をした2用途の合成になっている
- 直し方の方向: `anchorEl` と `getAnchorRect` を消す。`getAnchorRect` が要るのは、基準がトリガーと違う #7（SplitButton の外枠）だけ。そこも `ids.anchor` に外枠の id を渡せば、`useMotionPopover` の `getAnchor()`（すでに anchor の id を引く実装がある）と揃い、`anchorRef` の prop が消える

### 4. `isInsideOwnLayerTree` と `popoverTriggerIds` は到達しない

- 場所: `shared/ui/popover/MotionPopover.tsx:32-56, 133-142, 154`
- 問題: ポップオーバーの `onFocusOutside` で「自分の content から開いた層への移動は閉じない」を自前で判定しているが、zag はこのハンドラを呼ぶ前に同じ判定を済ませている
  - `interact-outside` の `isEventOutside` は、target が content の中なら outside にしない。子の層は `layerContainer` で content の中へポータルしているので、ここで必ず落ちる
  - さらに `exclude` が `layerStack.isInNestedLayer`（後から開いた層の中）を除外する（`dismissable-layer.mjs`）
  - さらに `followControlledElements` が `aria-controls` の先を除外する
- なぜ問題か: 35 行の DOM 走査と、モジュールレベルの WeakMap が1つ、`bindContent` の登録処理が、Ark の機能の再実装として残る。`data-scope`・`aria-labelledby`・`aria-controls` という Ark の DOM 表現に依存する箇所が増える（6 を参照）。読む人は「zag の判定では足りない場面がある」と受け取る
- 直し方の方向: `onFocusOutside` の上書きと `isInsideOwnLayerTree`・`popoverTriggerIds` を消し、「ポップオーバーとメニューの重なり」のテストが通ることを確かめる。落ちるテストがあれば、その場面をコメントに書いて残す

### 5. メニューの外へのフォーカス移動の判定も、zag の結果を使えば自前の走査が要らない

- 場所: `shared/ui/menu/MotionMenu.tsx:28-51, 95-114`
- 問題: `isInsideOwnMenuTree` は zag の `isTargetWithinMenuTree` と右クリックトリガーの判定を、`aria-labelledby` をたどる DOM 走査で書き直している。`prop("onFocusOutside")` が zag 自身の判定より先に呼ばれるためだが、`dismissable-layer.mjs` は `onFocusOutside` の直後に `onInteractOutside` を呼び、その時点の `event.defaultPrevented` は zag のツリー判定の結果になっている
- なぜ問題か: ADR-0043 は「自分のツリーへの移動は閉じず、zag の判定に任せる」と書いているが、実装は zag と同じ判定をもう一度書いている。サブメニューを使い始めると（DRAFT-53）、zag の判定と自前の判定の差がそのまま不具合になる
- 直し方の方向: `onInteractOutside` で受け、`event.defaultPrevented` なら何もしない、フォーカス起因（`event.detail.originalEvent.type === "focusin"`）なら `preventDefault` して `CLOSE`（`restoreFocus: false`）を送る。`isInsideOwnMenuTree` とそのテストは消せる

### 6. ADR-0043 と `service.send` の扱いが合っていない

- 場所: `docs/adr/0043-ui-primitives-ark-ui.md:50, 124`、`shared/ui/menu/MotionMenu.tsx:113, 139, 158`
- 問題: ADR は「`service.send` のような文書化されていない口は使わない」（50 行目）と書き、帰結では「共通のメニューフックが、閉じた後に移動先へ戻す」（124 行目）と書いている。実装は `service.send({ type: "CLOSE", restoreFocus: false })` を3か所で使い、「閉じた後に戻す」ではなく「戻しを起こさずに閉じる」。コードのコメントには内部仕様への依存が書いてあるが、ADR には無い
- なぜ問題か: `restoreFocus: false` を渡す公開の口は zag のメニューに無いので、使うこと自体は妥当だと思う。ただ、Ark を上げるとき（TASK-530）に確かめる項目が ADR から読み取れず、50 行目の規則と矛盾したままになる
- 直し方の方向: ADR に「メニューの `CLOSE` に `restoreFocus: false` を付けるために `service.send` を使う。対象は外へのフォーカス移動と `MenuLayerItem`。更新時はこの2つを確かめる」と書き、50 行目はサブメニューの Esc に限った話だと分かるようにする。124 行目は実装に合わせる。スクロールで閉じる `closeOnScroll`（139 行目）は戻しが要るので、公開の `api.setOpen(false)` で足りる

### 7. 「フォーカスを残したまま無効にするトリガー」の作り方が4通りある

- 場所: `shared/ui/IconButton.tsx:93-106`（`softDisabled`）、`shared/ui/menu/MotionMenu.tsx:143-149`（`disabled`＋`triggerProps`）、`features/scan/ui/scanModal/unregistered/RowMenu.tsx:22-36`、`shared/ui/SplitButton.tsx:64, 71, 85`、`features/library/ui/preview/WorkEditTagsField.tsx:60`、`features/library/ui/preview/WorkTagEditor.tsx:152`
- 問題:
  - メニューは `useMotionMenu({ disabled })` と `triggerProps` の展開で止める。見た目と `aria-disabled` は呼び出し側が別に付ける（RowMenu は `aria-disabled` と `aria-disabled:text-ink-4` を手書き、SplitButton は自前）
  - ポップオーバーは `IconButton` の `softDisabled`（click の `preventDefault` と Enter・Space の握りつぶし）で止め、さらに呼び出し側の `onOpenChange` でも弾く。二重のガードで、どちらが効いているのか読み取れない
  - RowMenu は `IconButton` を使っているのに `softDisabled` を使えない（`softDisabled` は zag の `data-disabled` を立てない）
- なぜ問題か: 「止める」と「無効に見せる」が別の場所にあり、片方だけ付け忘れても型でもテストでも気づけない。次にトリガーを足す人は、どの組み合わせが正しいのかを既存の4例から推測することになる
- 直し方の方向: 両方のフックが `disabled` を受け、トリガーへ展開する props（`data-disabled`・`aria-disabled`・開くキーの抑止）を返す形に揃える。`IconButton` の `softDisabled` は見た目と `aria-disabled` と自分の onClick のガードだけにして、Ark のトリガーを止める責務を持たせない。呼び出し側の `onOpenChange` のガードは消す

### 8. `triggerProps` の展開が任意で、メニュー8か所のうち4か所にしか付いていない

### 9. 出現の起点を16か所で手書きしている

- 場所: `shared/ui/menu/MotionMenu.tsx:185`（`origin` 必須）、`shared/ui/popover/MotionPopover.tsx:216`（既定 `var(--transform-origin)`）、各呼び出し箇所の `origin="top right"` など
- 問題: zag は positioner に `--transform-origin` を出しており（`popper/get-placement.mjs`）、flip 後の向きも反映する。ポップオーバーはそれを既定にしているが、全箇所が `origin` を渡しているので使われていない。メニューは必須 prop で、`placement` と同じ情報を文字列でもう一度書かせている
- なぜ問題か: flip したとき（パンくずの値は `flip: true`、画面下端近くのソートメニューなど）、開く向きと起点が逆になる。`placement` を変えたら `origin` も直す、という規約が各所に残る
- 直し方の方向: メニューも既定を `var(--transform-origin)` にして、`origin` の指定を全箇所から消す。motion がこの CSS 変数を `transformOrigin` として扱えるかは実ブラウザで確かめる。扱えないなら、ポップオーバーの既定は今も効いていないので、既定を消して必須にそろえる

### 10. WorkTagEditor がトリガーを2つ描き分け、差し替えのフォーカス移しと外側クリックの監視を自前で持つ

- 場所: `features/library/ui/preview/WorkTagEditor.tsx:71, 81-90, 162-179, 288-319`
- 問題: narrow のときは素の `IconButton`、そうでないときは `Popover.Trigger asChild` の `IconButton` を、同じ位置に別の型で描いている。幅が 320px をまたぐとボタンが作り直されるので、`bindTrigger` と `transferTriggerFocus` でフォーカスを移し替えている。インライン表示の閉じ方（document の capture 段の pointerdown）も、このコンポーネントに書いてある
- なぜ問題か: 作り直しは描き分けが生んだ問題で、その補修が ref コールバックの cleanup に入っている。インラインの閉じ方は、今回削除した `usePopoverDismissal` の縮小版を機能側に書き戻した形になっている。フォーカスが外へ移っても閉じないなど、ポップオーバー側と規則がずれていく
- 直し方の方向: トリガーは常に `Popover.Trigger` の1つにして、`onOpenChange({ open: true })` を受けた側で `isNarrow` を見て `openMode` を "inline" か "popover" に振り分ける（インラインで開いているときの再押下も同じ `onOpenChange` に来る）。ボタンは作り直されず、`bindTrigger`・`transferTriggerFocus` が消える。`aria-expanded` はインラインのとき上書きする。インラインの外側クリックは、残すなら `layer/` に置いて、ポップオーバーと同じ閉じ方の規則で書く

### 11. ポータル越しの React イベントの伝播を、箇所ごとに別の方法で止めている

- 場所: `features/player/ui/BarVolumePopover.tsx:51-52`（content で `stopPropagation`）、`features/player/model/usePopupDrag.ts:115, 124`（祖先側で `contains` を見る）、`features/player/model/useGlobalShortcuts.ts:60, 72`（window の capture 段へ移して `stopPropagation`）
- 問題: ポータルした層の中のクリックやキーは、React のツリーをたどって祖先のハンドラへ届く。これを、層の側で止める・祖先の側で弾く・グローバルの側で先取りする、の3通りで直している。`usePopupDrag` の分は最後の修正コミット（c0fa9b30）で入っている
- なぜ問題か: 祖先に onClick・onPointerDown・onKeyDown を持つ場所へ次にメニューやポップオーバーを置くと、同じ不具合がまた出て、また別の直し方が増える
- 直し方の方向: 規則を1つに決めて共通層に置く。`MenuPopup`／`PopoverPopup` の content で pointer・click・keydown の React の伝播を止めるのが素直だと思う（zag は document のネイティブのリスナーで動くので影響しない。`useDialogModal` の backdrop 判定は target を見ているので影響しない）。採るなら `BarVolumePopover` の2行と `usePopupDrag` のガードは消せる。採らないなら、祖先側で弾く方に揃えて design-system.md に書く

- 直し方: ツリーの判定・層の登録・セレクタを `shared/ui/layer/` の1モジュールにまとめる。`focusReturnTarget.ts` は層の概念そのものなので `shared/lib` から `layer/` へ移す（design-system.md の「…IME のキー判定は `shared/ui/layer/` で共有する」とも合う）

### S3. メニューとポップオーバーで既定値の置き場所が非対称で、呼び出し側に同じ値を繰り返させている
- 間隔（gutter）: ポップオーバーは `useMotionPopover` が既定（`MotionPopover.tsx:119` の `gutter: 6`）を持つ。メニューは既定を持たず、`MENU_GUTTER` を8か所で毎回渡している（SidebarAddMenu、LibrarySortMenu、FilesAddressBarMenu、WorkPlayButton、WorkMetadataActions、RowMenu、PlaybackRatePicker、SplitButton）。`useMotionMenu` の positioning の既定に入れ、`MENU_GUTTER` の export はやめる。6 は layer の定数1つにする
- `z-50` を `menuStyles.ts:6` と `popoverStyles.ts:3` に別々に書いている。design-system の階層表では1行（z-index 50）なので、`layerStyles.ts` の `panelFrameClass` 側に寄せる
- origin: `PopoverPopup` の既定 `origin = "var(--transform-origin)"`（`MotionPopover.tsx:216`）を使う呼び出しが1つも無く、死んだ既定になっている。逆に全呼び出しが placement と対になる origin を手で書いている（例: `bottom-end` → `"top right"` を6か所）。placement から origin を決める関数を layer に置いて取り違えを防ぐか、Ark の `--transform-origin` に統一する。統一すると flip したときも正しくなる

### S4. 「フォーカスを残したまま無効にする」の実装が3通りあり、コメントが実装と食い違う箇所もある
- `shared/ui/IconButton.tsx:60-106` の `softDisabled`（onClick と Enter/Space を握りつぶす）
- `useMotionMenu` の `disabled`（`MotionMenu.tsx:143-156`。`data-disabled` と capture の keydown）に加え、`RowMenu.tsx:33-34` が IconButton に `aria-disabled={busy}` と `className="aria-disabled:text-ink-4"` を手で付けている（`softDisabled` を使っていない）
- `shared/ui/SplitButton.tsx:69-91` と `ScanSidebar.tsx` の中止ボタンは、`aria-disabled` とハンドラ側のガードを手で書いている
- `RowMenu.tsx:13` のコメント「トリガーは無効にせず（フォーカスを落とさない）、項目だけ無効にする」は誤り。`disabled: busy` でトリガーも開かなくなる。その結果、項目の `disabled={busy}`（:42、:52）は開いている最中に busy になったときにしか効かない
- 直し方: 見た目と操作のガードを1か所（IconButton の `softDisabled` と、Button 系の同じ props）に寄せ、メニューのトリガーは `useMotionMenu({ disabled })` と `softDisabled` を組み合わせる形に揃える。RowMenu のコメントは実装に合わせて直す

### S5. タグ追加ポップオーバーの配線が2か所に重複している

### S7. `LibraryBreadcrumbs` が React の管理下の DOM の id を書き換え、内部のクラス名に依存している

### 全体所見

置き換えそのものはきれいに済んでいる。旧フック・旧 CSS・floating-ui の残骸は無く、テストも fireEvent から userEvent への移行で期待をおおむね保ったまま書き直されている。大きな問題は2つ。共通層の中に、同じ役割の実装が2つずつある（ツリーの判定、WeakMap による登録、セレクタ、gutter・z-index・origin の既定、ソフトな無効化）。ADR-0043 は、禁止した `service.send` を使っていることを記録していないうえ、完了していない「項目定義の共有」を完了と書き、実装の手順を積み上げて膨らんでいる。マージ前に M1 と S1 の ADR の整合だけは直したい。S2〜S5 の重複の整理は、DRAFT-53（右クリック）で層の使い手が増える前に済ませるのが得策。
